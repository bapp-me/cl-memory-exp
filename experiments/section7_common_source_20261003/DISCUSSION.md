## 共同基底

- 从原始题的 `pi-result.json` 重建题面、可见 assistant text/toolCall、toolResult，排除 reasoning、隐藏评分和参考解；按源任务顺序赋予 0–47 的库内序号。No Memory 原运行不保存跨题库，不能把它的空 `memory-after` 当作可复用轨迹。
- 抽取逻辑已对旧 Jaccard 的全部 48 条已保存源 episode 逐字段校验。所有方法共享同一重建库，来源说明应明确为归档的 No Memory 执行观察，不称当前 reader 自己的历史。

- 不按隐藏通过标签过滤源题；失败、不可评分源同样保留。检索后才离线关联配对来源和既有评分 mask。

## 离线实测

同一 48 条库、同一批 48 道复杂题，仅重算检索和注入，不调用模型。46 是既有可评分目标分母；对应源出现仅表示 provenance 覆盖，不等于适用、正确或已被模型使用。

| 配置 | 平均每题注入字节 | 对应源覆盖 /46 | 解释 |
|---|---:|---:|---|
| 原版 bounded ICL，48,000 字节预算 | 45,877 | 7 | 每题均为最后 8 条源轨迹，索引 40–47 |
| 原版全文 Jaccard top-3 | 12,209.6 | 46 | 48 道执行题也全部覆盖其对应源 |
| 全文 Jaccard top-2 | 8,415.6 | 44 | 比 top-1 多装内容，却未补上两道对应源 |
| 全文 Jaccard top-1 | 4,899.4 | 44 | 对比 top-3 注入字节少约 59.9%；954、269 对应源排在第三 |
| 只按源题面 Jaccard top-1 | 5,050.1 | 45 | 734 对应源未命中；这是改变检索字段的另一因素 |
| 只按源题面 Jaccard top-3 | 14,388.9 | 45 | 不能因为题面更短就预设这种排序更好 |

这些是字节，不是 provider tokens。冻结 ICL 的相同前缀可能获得缓存收益，因此不能按字节直接推算金额。

本次具体可逆探针把 episode 内层 JSON 展开，使用紧凑 JSON，并对重复的至少 160 字节完整字符串叶子建立定义/引用；全部通过恢复等价断言。仅结构整理可省约 6.6%–7.1% 注入字节，测试范围内没有额外重复长字符串可去重。这不排除其他子串压缩，但不足以继续把 7.3 H1 的整段精确去重作为这批新基底的首要优化。

另一项有损探针仅保留“完整原始题面 + 未经验证的最终提交代码”：48 条共 141,489 字节，比完整库少约 41.3%。若保持原 ICL 相同的最后 8 条，注入由 45,877 降至 24,237 字节，少约 47.2%；若压缩后重新填满 48 KB，则装入最后 16 条、44,307 字节，几乎用回原注入量。后者增加覆盖与前者节省输入是不同目标，不能混称单因素省 token。

## 优化建议与边界

1. **优先检验 Jaccard top-3 → top-1。** 先保持全文评分字段、同一源库、原完整 episode 表示和相同生成配置，仅减少数量。优势是零新增 writer 调用、改动简单、节省输入潜力大；风险是漏掉必要的第二/第三条经验。覆盖 44/46 不等于结果只能达到 44/46，更不等于一定保住旧的正确率。
2. **ICL 用“完整题面 + 最终提交代码”作为有损精简对照。** 保持原选择的 8 条及顺序，先隔离表示变化，不拿省出的空间添加其他条目。题目约束保留，但过程观察、失败与纠错会被删掉，必须验证下游质量。它仍只有 7/46 对应源覆盖，压缩没有解决 FIFO 的相关性不足。若按相关性挑源，应另名为检索变体，而不能仍宣称普通 FIFO ICL。
3. **结构整理作为后续小优化。** 可逆只是内容恢复性质，不保证模型解释完全等效；本次约 7% 的字节下降也不等于总 token 下降 7%。
4. **暂不引入 LLM 摘要、embedding/reranker 或按需记忆工具。** 这些可以讨论，但当前全文 top-3 已全覆盖对应源，先检验便宜的数量/表示调整更容易解释。按需取回第 2/3 条有希望折中，但会新增工具调用和“何时补读”失败模式，应单独预算与测量。

旧 46 个有效目标中，ICL 总 token 为 1,772,238，其中输入含缓存 1,693,234；Jaccard 总 token 为 574,109，其中输入含缓存 520,604。输入开销值得优先处理，但总用量也受每题生成轮次影响，不能只靠缩短记忆宣布成功。

## 建议的执行顺序，尚未批准新增对照

基础范围仍是 48 道复杂题 × 两方法 × R=1，共 96 个 solver task；简单题直接复用归档，无新 writer LLM。

建议先从同一开发集冻结 4 道经评分契约检查的题，做四条件：ICL 原样、ICL 同条目精简、Jaccard 原样 top-3、Jaccard 原样 top-1，共 16 个 solver task。检索边界、轨迹大小和契约状态可用于预登记选题；不能运行后挑掉退化样本，不能称未见验证集。隐藏评分不进入源库或检索。

小批只做筛查：记录逐题正确性/已预登记质量检查、全请求输入与输出及缓存 tokens、工作工具数、错误后恢复、延迟；如缺少可靠价格/账单，金额保持未知。保持 GLM-5.3-Flash high、既有工具/执行预算及评分版本，不顺便换模型或降低 reasoning。R=1 不能证明稳定非劣。

筛查后再决定每方法采用原样还是候选版本完成全量。若最终选择配置与小批完全相同且无环境/协议修订，每方法的 4 道可计入最终 48 道，剩余 44 × 2 = 88，累计 104 个 solver task；若配置改变，小批只能作开发记录，完整重跑则累计最多 112。不得自动追加重复、补题或扩展到四臂全量 192。

单个 solver task 可能含多次 HTTP 请求；以上不是 HTTP 请求数或金额硬上限。优化效果未知，不把旧 token 量当本次预测。需要在用户选择后再冻结正式协议和停止/费用规则。
