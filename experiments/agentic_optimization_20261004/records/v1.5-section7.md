### 7.2 失败分类与观测：保留证据规则，降低重复分析成本

#### 7.2.1 三个正交维度

结果状态＋可多选机制标签＋证据等级。结果区分成功、可评分失败、资产不可评分、基础设施中断、协议无效、观测缺失、未完成；正常预算耗尽/无效动作属于表现。

| 机制标签 | 定位 | 证据要求 |
| --- | --- | --- |
| EVAL_CONTRACT | 题意、断言、参考、依赖、提交契约 | 规范、实际调用及性质检查 |
| INFRA_PROTOCOL | 传输、沙箱、恢复、权限、调度 | 错误码、状态、请求链 |
| TASK_EXECUTION | 参数、工具、语法、终止、正常预算 | 可见动作与终态 |
| OPPORTUNITY_SOURCE | 是否有可用经验、源质量 | 前序合法来源，不存在机会不算检索失败 |
| WRITE_ADMISSION | 未写入、误拒绝、重复写入 | 候选/操作/状态变化，允许合理 NOOP |
| REPRESENTATION | 丢条件、失真、过度泛化 | 原文和实际表示，需语义审查 |
| RETRIEVAL | 可读库内相关内容未找回 | query、候选、排名、过滤 |
| PACKING_VISIBILITY | 找到但未进入模型可见上下文 | 实际请求及工具返回映射 |
| USE_TRANSFER | 已可见经验未正确适配/执行 | 动作与干预，不靠自称使用 |
| UPDATE_RETENTION | 后续更新使必要信息失效 | 多时点快照；正确替换旧规则不是遗忘 |
| SCOPE_INTERFERENCE | 无关/过期/跨项目干扰 | 作用域、当前规则、竞争解释 |
| COST_UTILITY | 无收益输入、重复操作、维护过重 | 质量与全角色成本 |

未主动搜索、读取过早停止、后台未提交可作可观察子标签，不另建庞大分类工程。无调用不等于本应调用；多标签次数不相加当失败任务数。

#### 7.2.2 证据等级

D0 为直接事实；D1 为人工/LLM 根据引用提出的语义候选；D2 为同起点受控变化的干预支持。LLM 标签不能升级为因果证据。

保留 unknown 和竞争解释。源 ID 覆盖不等于保真，AST 重合不等于使用；没有相关性真值不报精确 recall，没有多时点探针不报真实遗忘率。

#### 7.2.3 指标获取方式

| 类别 | 内容 | 工作 |
| --- | --- | --- |
| A0 已有直接记录 | 成败、分母、配对、usage、终态、工具量 | 直接读取，零新增模型调用 |
| A1 离线推导 | 工具分项、历史规模、源距离、旧检索/包装 | 脚本重建并验证一致性 |
| B 新接口埋点 | 主动搜索链、读取范围、技能版本、后台/子 agent 调用 | S0 上增量补 hook |
| C 语义审查 | 条件、适用性、失真、错误推广 | 人工或离线 LLM，保存引用与 unknown |
| D 新受控实验 | 因果收益、质量保持、损害、遗忘 | 有限分叉/重复，日志不能替代反事实 |

#### 7.2.5 后续审查预算

默认不再每轮复刻 324 条全量 LLM 审查。所有机械指标全量重算；语义审查优先覆盖 S0/S1 结果变化、主张相关机制和预登记成功/失败对照。

#### 7.4.2 Harness 路线的有界决定

**2026-10-03 已决定采用 B。** Pi 接单项工具可行，但保留 Hermes 原生后台 fork、会话/压缩与技能状态需要额外生命周期桥接，超出薄适配。完整 A 的工程估计为 12–21 人日，B 为 6–11 人日，均非实测工时；不包括 S1、完整基准及最终场景。决定、拟用原生能力/初态/权限及 N/J 重新登记见 [base-system-decision](experiments/section7_s0_audit_20261003/records/base-system-decision.json)；未批准的后续范围见 [canary 草案](experiments/section7_s0_audit_20261003/records/canary-proposal.json)。不长期维护两套主要 Harness，旧 Pi 成绩保持历史身份。

**路线 A：Pi＋复用 Hermes 记忆子系统。** 只有能以薄适配保留主要原生行为时采用。允许接口转换、沙箱边界、日志代理和调度屏障；不允许将主动搜索固定成一次 top-k、移除关键维护、重写大段 loop 后仍称直接复用。

**路线 B：Hermes 原生 Harness＋现有 benchmark/观测适配。** 若路线 A 需重写 loop、session 生命周期、skills 执行或后台框架，或无法重建核心状态，则采用 B，并一次性重冻共同配置。不要同时长期维护 A/B 两套研究系统。

用依赖图、实际适配清单、原生保真及可回归性决定，不先在两个路线跑大规模性能竞赛。完成一次只读审查和必要无模型接口 spike 后必须给决定或明确阻断项；不通过连续补丁无限拖延。

采用 B 时重新登记 N/J；旧 Pi 成绩只放历史附录，不能混成同底座排行榜。如果 B 也不能满足权限、快照、GLM 兼容和成本记录，停止并报告缺口，另行决定是否评估一个替代底座，而非默认从零造系统。

#### 7.4.3 接入验收：fixture 优先，小规模在线随后

先冻结拟用 S0 profile。离线 fixture 覆盖：空历史、存在旧会话、搜索无命中、读长片段、记忆满、更新/删除或待审批、skill 读写、只读拒绝写回、后台完成/超时、恢复幂等、不同用户/项目隔离、usage 缺失。

**默认在线 canary：S0 一组 12 个任务、R=1。** 复用已访问的四题代码协议流和完整八题 BabyAI：

```text
代码：raw:BigCodeBench/296 → raw:BigCodeBench/325
   → new:BigCodeBench/325 → new:BigCodeBench/296
BabyAI：38, 39, 36, 37, 53, 52, 54, 55
```

沿用已有 manifest 的相对顺序与环境 seed；这些短流用于协议/观测验收，不因代码契约 pending 就宣称质量提升，不充当完整长流。不同环境独立空记忆起步。

仅在 Harness/共同接口变化导致 N/J 也需重新验收时，各加同一 12 任务；因此三组 canary 上限为 36 次任务执行，不是默认都要跑，也不是 36 次 API 调用。复杂维护调用另计。最终 batch 在运行前一次确认，不自动继承旧六组授权。

长历史、搜索分页、技能规模、上下文溢出与后台队列先用冻结合法历史/合成 fixture 检查，不为压测立刻重跑 96 题。导入旧合法轨迹作为状态压力测试要标“回放 fixture”，不冒充 S0 自己积累的在线记忆。

验收至少证明：原生功能可触发、实际请求与来源可追溯、状态可重建、隐藏信息隔离、费用含辅助角色。正常自主策略未写入可记 NOOP；若要验证写入能力，用单独显式要求记住/调用工具的能力 fixture，不把强制提示偷偷带入正式性能流。

下列为放行硬条件：

- 所有适用任务/调用有唯一 ID、终态、提交或环境终止证据；返回 usage 的调用可对账，未知显式保留。
- 记忆搜索/读取到实际上下文、修改到已提交状态、后台/子 agent 到父任务的证据链可追踪。
- 只读不写回；跨组/profile 不共享可写状态；所有读取限制对主 agent 和辅助角色一致。
- 原生关键能力没有因适配静默关闭；已知不可观测部分须限制相应机制主张。
- 正常模型答错不算观测验收失败；隐藏泄漏、日志漏计和状态无法恢复才阻断放大。

验收通过仅说明 S0 可执行，不说明 S0 优于 Jaccard 或成熟系统在本任务上一定有效。

### 7.5 在 S0 上选择一个问题并开发 S1

#### 7.5.1 进入条件

问题必须同时满足：在正常工作的 S0 上实际出现；有合法来源和动作/成本证据；与期望场景相关；不是确定的接线、格式或预算拒绝；原生配置/简单替代尚不能充分解决；有可负担的质量指标和反驳实验。

不要求小样本就证明统计稳定，但不能凭一个模糊失败定主线。优先寻找跨至少两个不同目标/实例的同类证据；若只有单例，明确保持案例诊断身份。需要代表办公/数据场景的主张时，要有相应非代码证据，不以八题 BabyAI 替代。

旧 H1–H5 是候选池。S0 已消除的瓶颈不继续优化；H1 只有在新系统仍有显著可逆冗余且总成本值得改时保留。H2 的条件适配须重新出现并排除契约问题。H4/H5 默认不再开付费支线。

#### 7.5.2 一个机制卡，而不是一套新平台

登记现象、范围、唯一主要改动、竞争解释、最简单替代、预期变化、不应变化项、失败条件、所需记录、任务/调用/费用包络。

S1 可以改已有组件而非新增模块。原始来源可恢复、版本和权限属于共同工程要求；不能把新增 provenance 字段本身当研究贡献。机制与最近邻核查在编码大规模方案前完成。

#### 7.5.3 最小有判别力实验

先用无模型构造验证可逆性、映射、权限和状态；再做同期同起点分叉。默认首批最多四个已登记且过 G0 的目标，S0/S1 两臂、R=1 共最多八次 solver 任务；确需第三臂简单替代 C 时为最多十二次，运行前确认。它们不是原 H1 的默认四题，也不是新结果已经出现。

冻结历史来自明确的同一个合法状态；只改变研究因素，不额外给 S1 gold 来源、不增加未来经验。S0 同期重跑，不拿旧成功记录当唯一对照。交替臂顺序并记录 cache/时段，不能假称模型随机性完全可控。

四题 R=1 零下降只是一轮筛查，不能证明非劣性。质量门槛、预期节约、工具和缓存限制在看到新结果前确定，不默认继承 H1 的 20%。按最小可接受收益和实际方差确定后续证据强度。

S1 改 writer/更新会改变未来历史，必须从相同初态跑独立完整在线流，不能只把旧 S0 后半段接成 S1。只改 reader 时，同快照诊断有用，但正式系统证据仍须检查新轨迹反馈到后续 memory 的闭环。

#### 7.5.4 两类比较分别报告

- 同起点干预：隔离机制，说明来自哪个历史与环境，禁止写回。
- 端到端 S0/S1：各自生成历史，反映误差累积、读写和执行共同作用。

对读取/搜索机制，S0 原生主动访问是必要对照，不只与被动 Jaccard 比。对压缩机制，加入简单摘要或无损表示；对条件校验，控制一般提醒和额外推理预算。不要一次把压缩、检索、条件检查、writer、模型全改后声称定位单因。

#### 7.5.5 有界迭代与停止

默认一个主要机制，允许一次根据明确失败证据的修订 S1r。每轮只补改变决策所需的分析/运行，不自动全量重标注和六组重跑。

若简单替代达到同效果，采用简单方案并缩小创新主张。若只有质量下降换 token，报告 trade-off，不称 Pareto 改善。若主要改进及一次有理由修订仍不能支持增量价值，结束该机制，交付负结果或经用户确认调整目标；不自动转向再加一层架构。

### 7.6 阶段性 CL-Bench 验证

预留 `sales_prediction/default` 和 `blind_spectrum_monitoring/default`，具体接入未验收。[E4] 兼容 canary 不触及正式实例；无法避免结构暴露时记录范围，不把它隐藏。

以同一冻结 S0 为参照，阶段比较 S0/S1，必要时 S1r。N/J 的参照只建立必要的一次；后续未变且可比时复用。不要每个候选跑全部旧方法。

各版本独立空初态，不搬开发记忆。只看预定义聚合/阶段/成本；逐例设计新机制会改变数据身份。验证失败可以导致收缩主张，不因不利结果换环境。

### 7.7 收敛、冻结和交付

进入最终测试需满足：S0 闭环可运行；S1 只针对一个已观察问题；必要简单替代/消融已做；质量和全角色成本可审计；所称稳定性有相应重复而非 R=1；没有未处理的严重协议/评分缺陷。

完整系统交付包含原生来源、适配、可关闭的 S1 开关、配置、恢复、最小示例和明确限制。Project/Global 仍是场景要求，不能在收尾时扩成新论文问题。
