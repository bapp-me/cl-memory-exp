# CL-Bench：同一 GLM 下的跨会话记忆系统比较

**版本：1.0｜日期：2026-10-04｜状态：方案确定，尚未实现适配或运行。**

目标：比较简单记忆管理和成熟 agent 系统在连续任务中的质量、成本、可靠性与经验交接情况。不是预设新算法，也不是仅改变 memory 模块的严格消融。主模型相同不代表系统提示、工具编排和辅助计算相同。

本轮只提交调研、方案与声明式配置；本地 Codex 负责适配、有限验收和执行。已停止的两个资格案例不恢复，旧成绩与评分口径不覆盖。入口见 [LOCAL_CODEX_TASK.md](LOCAL_CODEX_TASK.md)。

## 2. 环境、数据与会话边界

先做 `database_exploration/default`，通过后做 `codebase_adaptation/default`。调研快照为 CL-Bench `5f8c50eb1e84b2eda2ef4faff757dfc812a0ea26`；本地开始时复查当前版本，固定数据、schedule、工具/评分版本与镜像 digest。[S1–S2](SOURCES.md)

- Database：当前默认 40 个问题，前 20 / 后 20 为迁移前后。保留原生 QUERY/ANSWER、查询预算、反馈与计分，不将隐藏答案或参考 SQL 交给任何主/辅助 agent。此环境已有开发暴露，不重新称未见验证。
- Codebase：当前默认 tablib 9 题、tenacity 10 题，共 19。每题恢复其官方 base commit，不携带上一题代码补丁到下一题；保留许可的项目知识和历史。隐藏 test_patch/参考 patch/评分代码留在独立 evaluator。
- `instance` 是一个完整问题/issue，不是一次模型响应或 QUERY/Bash 调用。同题正常续会话；仅在 instance 完成后新建下一会话。不得逐工具调用清空上下文。
- 每个方法×重复×环境一个独立实验身份与 home。数据库迁移不清空记忆；代码库切换记录 project_key，原生项目路由保留。同一环境流的既往合法历史可被该方法访问，禁止跨方法、跨重复、跨环境复制经验。
- 代码项目工作树可按 base commit 重建，但逻辑项目路径保持稳定；记忆 sidecar 不随 `git reset` 删除。不同仓库用不同 project_key，不把随机 Docker 路径误当新项目。全局/项目路由差异单列为系统差异，不强行伪造完全等价的原生存储结构。
- 冷启动不加载研究者既有 MEMORY/USER/skills、开发答案或 evolved skills。工具使用说明与合法仓库文档各组等价可见。

CL-Bench Codex/Claude 的 `single_conversation=false` 已支持跨 instance 新会话；`reset()` 是整流硬重置，不能拿它代替每题切会话。[S4–S5](SOURCES.md)

## 3. 256k 与压缩

本方案统一 **256k = 262,144 tokens**，它是每个模型上下文的上限，不是整个任务的累计 token 预算，也不是永久记忆库容量。

为输出及工具包装预留 16,384 tokens，正常触发目标为 **245,760 tokens**。解释用户的“超过就压缩”为：下一请求预计会使上下文超过可用上限时，先压缩再发送，不能等 provider 拒绝后才常规处理。主/子 agent 和摘要/维护模型均不得获得更大的上下文优势。

保留各框架原生压缩算法，统一上限及尽可能对齐的触发目标，记录实际计量器、阈值、压缩前后内容与开销；不强行把所有摘要提示改成同一套。精确 tokenizer 不可得时标估算，不宣称跨协议逐 token 完全相等。[S6–S8](SOURCES.md)

原 48KB 记忆注入/证据预算不继承到本轮。Jaccard 仍固定 top-3，但所选内容过长时通过 Pi 的有界摄取与压缩适配处理，不静默丢弃整条来源。所有压缩均记录，不能借“压缩”偷偷再跑一个检索器。若无法不超窗地压缩过长输入，先在适配阶段解决，不进入正式流。

配置为 256k 不能提升服务真实能力。若账户所用 GLM/协议不支持该窗口，记录阻断；不可只改元数据假装支持，也不静默降为 128k/200k。若 provider 明确使用 256,000 的十进制口径，提交一次共同数值修订再冻结，不让各组各解释各的。

## 4. 核心协议：每题经验处理完成才进入下一题

```text
同一任务内执行
→ 冻结提交产物/环境终态
→ evaluator 评分，只交付原协议允许的反馈
→ 封存该任务合法轨迹与末事件水位
→ 完成已启动维护；必要时触发针对末水位的原生维护
→ 等待子任务、存储/索引提交，形成一致快照
→ 登记 completion barrier 与记忆版本
→ 新建下一任务会话，重新加载刚提交的长期状态
```

**在 barrier 通过前，不把下一题内容交给维护模型，也不提前构造下一题的记忆提示快照。** Codex 在下一会话 startup 才触发的工作，必须通过无未来题目的维护阶段前移，或在正式题目输入与记忆快照建立前完成；只延迟 `respond()` 不一定够。

完成不等于必须产生新笔记。允许 `completed_changed`、`completed_noop`、`completed_staged`；后者表示审批待定的内容尚未进入 committed memory。三个状态均要有真实维护终态与版本证据。源轨迹归档与衍生记忆生成分别记账，不能把“保存了 JSONL”当作“完成总结”。

未触发、不符合 idle 条件、失败、超时、还在运行、存储提交未完成均不得伪装成 `completed_noop`。期望有任务边界维护的系统如果只因为触发门槛未执行，应先修调度，不继续跑空转记忆流。合理的内容筛选可拒收，但需记录决策状态，不保证每条轨迹写出事实。

以 `(run_id, instance_id, source_watermark)` 去重：已有任务已覆盖该水位就不重复启动；中途 review 未覆盖最终合法反馈时才处理尾部。不允许维护子任务再次触发同类维护而递归放大。正常任务内原生前台写入/维护不禁用，产生的全部费用计入。

每个任务边界初始等待上限 600 秒、维护链模型请求最多 32 次；这是本轮执行保护，不是上游默认。原生更紧限制要登记；达到预算且仍不完整就暂停该流，保留本题分数与所有费用。仅传输故障按 manifest 重试；不得为了写出非空内容重复调用。恢复从可靠提交点继续，不重跑已经固定的业务提交。

## 5. 适配取舍

按以下顺序解决不兼容：官方设置/环境变量 → 官方 SDK/事件接口 → 最小可审计调度或日志补丁。所有补丁保存上游 SHA、diff、原因、影响范围。不开一轮大规模框架重写。

允许的改动包括：GLM provider、工具协议转换、上下文声明、记忆 eligible/触发时机/等待句柄、日志采集和沙箱隔离。不得擅自替换 writer 提示、把另一套摘要器冒充原生 memory、放宽业务权限或修改 grader 以适配某组。

某组无法在合理适配范围内满足模型一致性、256k、状态交接或任务隔离时，标 `BLOCKED`，让其他通过的组继续；不以不兼容当算法得零分，也不为了凑齐六组静默降级。正文缺失但全请求成本可对账的子角色可标 `LIMITED_OBSERVABILITY`，只支持相应边界内的结论。总请求是否覆盖都无法确认时，不进入完整成本比较。

## 6. 运行规模、预算与放行

首轮 R=1，六组全部通过且当前 schedule 不变时为 `6×(40+19)=354` 次任务执行。不是 354 次 API 调用；记忆、压缩、子 agent、canary、故障均另计。默认不追加 R=2、全量语义审查、连续会话对照或新的优化轮次。

每条依赖流串行，独立流可以并发；初始全局模型请求并发上限 4，包含后台和子 agent。依据账户容量可在正式流前一次调整并冻结，不沿用旧实验的峰值或不限额授权。业务 query/command/timeout 以锁定的官方配置为准，主模型单请求输出目标上限 8192；真实支持情况和辅助原生上限写入 runtime lock。

先进行离线 fixture，再每组必要的模型接口/记忆 canary；不要用完整 40/19 题来调试日志。完全相同配置下按正式顺序运行的前缀 canary可以延续为正式流，记录复用，不双计；改变配置后的 canary是测试成本，不能混入正式结果。

当地执行前锁定版本、任务清单、模型路由、预算、反馈、异常政策与验收证据。用户让本地 Codex 执行后，已批准范围内通过验收即可继续，不为每条正常调用重复请示。账户授权或批次费用包络缺失时一次补足；本次文档提交本身不调用模型，也不把已关闭旧批次授权挪过来。

## 7. 分析与结论

报告每环境正确率/原生 reward、业务动作、全部已知模型用量及缓存、端到端时间、维护等待、状态规模、来源曝光和异常。数据库按迁移前后、代码库按仓库分别展示，不把后半段快了直接认定为学习。

主表是完整系统配置比较；Pi 三组才具有较近的共同底座。跨框架分差不可全部归因于 memory。R=1 不声明稳定排名、统计非劣或不存在负迁移；不拼接旧 AgentCL 分数作同期对照。

离线审查优先解释结果差异、昂贵个例、迁移错误、未触发/未提交与重复查询；主张需要反事实时另设实验。首次汇总最多选 12 个独立目标做重点语义复核，其余先做机械统计，不默认重建大规模标注工程。必须先按 [观测要求](OBSERVABILITY.md) 保存材料，不能指望离线分析恢复从未记录的信息。

本轮合格交付是：可运行配置＋兼容性/限制表＋可追溯结果和成本＋值得或不值得继续研究的具体问题。Notepad/Jaccard 足够好也属于有效结论，不以必须胜过它们作为继续加机制的理由。
