# Hermes 维护超时诊断与三题重跑

2026-10-05，时间显示为香港时间。用户要求排查维护耗时，并重跑三道受错误仓库提示影响的题。本次诊断没有调用模型；三次重跑共 23 个实际请求、162,573 tokens。

## 维护为何超过十分钟

**主要问题是一次服务端失败和一次工具参数重复生成，叠加在同一个 600 秒等待窗口里。** 不宜据此断言正常记忆整理就需要几十分钟：Hermes 此前 9 个已完成任务的维护等待中位数为 **32.765 秒**，最长 **141.374 秒**。

第 10 题已经答对，业务提交发生于 2026-10-05 02:24:04.564。后台工作是在维护可供以后使用的 `clbench-db-quiz` 技能：读现有规则，生成补丁，再调用工具写入。这比只输出一段总结多了模型—工具往返，但本次超时的大部分时间并未形成有效持久化更新。

| 提交后的阶段 | 相对提交开始时间 | 请求耗时 | 实际观察 |
|---|---:|---:|---|
| 主会话收尾 | +0.12 秒 | 45.88 秒 | 答案已提交后，主 agent 结束当前回复 |
| 会话标题生成 | +46.22 秒 | 1.30 秒 | 只给会话命名；与技能维护并行，不应计作记忆 writer |
| 技能 review 的第一次响应 | +46.35 秒 | 127.41 秒 | 输出 910 tokens，然后调用 `skill_view` 读取现有技能 |
| 下一次请求失败 | +173.97 秒 | 196.00 秒 | HTTP 200 流尾带有 `error.code=500 / Operation failed`，没有 usage |
| 原生恢复请求 | +370.11 秒 | 213.10 秒 | `skill_manage` 参数反复生成，用满 16,384 输出 tokens，JSON 未闭合 |
| 提高至 32,768 后重试 | +583.53 秒 | 73.07 秒 | 产生合法 JSON、4 个 patch、仅 1,906 输出 tokens，但此时等待窗口只剩 16.47 秒 |

最后一次响应完整到达是在提交后约 656.6 秒，已经超过 600 秒截止。停机快照中的技能正文与上一题快照相同，review 状态仍未完成；不能把稍后收到的合法工具参数当成“已执行、已保存记忆”。标题调用与 review 有重叠，上表不能直接逐项相加作为墙钟耗时。

### 输出用满不是因为有十几万字值得保存

异常 `skill_manage` 调用的参数长 **60,816 字符**。其中同一段 **990 字符**的 `new_string` 被完整重复 **54 次**，出现 **56 次 `operations` 键**，没有任何 `name` 键，最后停在未闭合的字符串。此次 16,384 输出 tokens 中，报告的 reasoning 只有 **644**；主要预算消耗在重复的工具参数上。

下一次相同输入的重试只用了 1,906 输出 tokens，工具参数长 3,168 字符，包含四个正常结构的 patch。这说明首次 16k 耗尽不能简单解释成“维护内容本来就需要更长输出”。输入约 17,211 tokens，也没有接近总窗口上限。

### 为什么框架没有挡住重复

核对了实际运行镜像里的 Hermes 源码哈希，与本地锁定源码一致。该版本 `_abort_reason` 在发现 `has_tool_calls=True` 时直接返回，后面的文本重复检测不会检查这些工具参数。工具调用截断随后走“增大输出预算并重试”的路径。本地直接调用该原生函数的离线分支测试也确认了这一点。

这是工具参数重复检测的覆盖缺口。当前没有替换 writer 提示、降低 reasoning 或修改原生拒绝/重试策略；本轮是完整系统比较，这类修改需要单独登记，不能悄悄加入某一组。

### 排除了什么、还有什么未知

- 这六个提交后请求的本地并发门等待均为 **0 秒**，所以不是本地 50 并发信号量排队。
- 1.3 秒请求的系统提示和返回值明确是生成标题。此前进度消息将其称为普通记忆检查，现已更正。
- 已确认远端返回服务端错误，但现有日志没有逐 chunk 到达时间或首 token 时间，不能把 127 秒、196 秒进一步精确拆成远端排队、计算和网络传输。
- 网络错误恢复提示出现在重复生成之前；这不能证明提示本身导致了循环。
- 单纯增加到 40 分钟或继续抬高 token 上限，不能保证解决重复生成。当前 600 秒等待未改动。

证据见 [请求时间线与重复统计](records/hermes-maintenance-latency-diagnosis.json)、[实际镜像源码核验](records/hermes-image-source-verification.json)。它们只公开角色、用量、时间和哈希，原始请求、技能文本和模型输出留在私有审计区。
