# Database 题前、题后记忆快照

本目录按用户授权，保存本轮 R=1 的 Notepad、Codex、Claude Code、Hermes 四组各 40 道 Database 任务的题前与题后记忆，共 **320 份快照**。这是各题边界的记忆文件内容；不包含 Codebase、会话日志、模型请求副本、原生数据库、Git 内部文件或评分器私有记录。

## 大小与范围

下表是未压缩、跨快照不去重的文件内容字节数，不含本说明、索引或目录等开销。保留 Hermes 的使用统计、维护账本和空锁文件，与用户指定的 15.710 MB 口径一致。

| 方法 | 题前 40 份 | 题后 40 份 | 合计字节 |
|---|---:|---:|---:|
| Notepad | 15,220 | 15,690 | 30,910 |
| Codex | 5,870,004 | 6,216,687 | 12,086,691 |
| Claude Code | 692,991 | 731,522 | 1,424,513 |
| Hermes | 1,052,559 | 1,114,947 | 2,167,506 |
| **合计** | **7,630,774** | **8,078,846** | **15,709,620** |

共 2,905 个记忆文件实例；其中 6 份快照没有记忆文件，仍用 `.snapshot.json` 明确保存空状态：Notepad 第 1 题题前、题后及第 2 题题前，以及三个原生框架的第 1 题题前。Hermes 管理文件共 1,092,275 字节；剔除它们后的纯内容为 14,617,345 字节。重复快照中的相同文件照常保留，因此总量不代表唯一知识量，也不等于单次模型输入大小。

## 目录与来源

路径格式为 `<方法>/task-<三位零基索引>/<before|after>/`。例如 `codex/task-039/after/` 是第 40 题维护完成后的记忆，`before` 是该题开始时的记忆。

- Notepad 将原始 `memory-before/after.json` 中的 `notepad` 字符串按 UTF-8 写入 `notepad.txt`，不重新摘要或改写。
- 三个原生框架保留记忆文件的原相对路径和原始字节。Codex 包含笔记、摘要、提取来源和技能；Claude Code 包含项目 auto memory；Hermes 包含 memories、skills、pending 路径中实际存在的文件及其管理文件。
- 题后文件取自选定任务的最终状态包；发生恢复的任务按正式结果索引选择已恢复的状态包。题前文件按原 `memory-before.json` 的 SHA-256 从上一题已提交状态重建；必要时仅接受当前状态包中哈希一致的文件。原始哈希不匹配会终止导出。
- Codex 的批次整合间隔和历史调度变更照实保留；快照不推断未落入记忆文件目录的原生数据库状态，也不声称完整封装了框架运行环境。

每个快照的 `.snapshot.json` 列出文件大小、SHA-256 及原始 JSON 字段或 tar 成员来源。总 [manifest.json](manifest.json) 记录全部快照索引和源文件哈希。源文件仍在本地私有目录中，没有被修改或整体上传。

## 校验

在实验目录下运行：

```powershell
.local\clbench-venv\Scripts\python.exe -X utf8 export_database_memory_snapshots.py --verify
```

也可使用 Python 3.11+ 执行该脚本；`--verify` 只依赖标准库和本导出目录，无需私有源文件、凭据或模型调用。校验覆盖 320 个快照身份、6 个空快照、全部文件哈希、分组大小及额外/缺失文件。

导出前已扫描常见 API key、GitHub token、私钥和 Authorization 字段，并检查全部 160 个选定任务配置中的已知本地凭据；未发现匹配。该定向检查不能保证识别所有潜在敏感值。
