## 1. 已决定的范围

这些是候选失效链，不是“memory 导致全部错误”的结论。尤其不能把已经上传的全历史目录直接挂给受测 agent。

**Claude：**核对 Q21 后、Q23 前/后、Q25 前/后的价格笔记、索引和真实写入事件。定位“Q21 没有 prc_v2”首次进入哪个请求、哪些历史材料当时可见。区分历史事实被写反、原写入者未获得来源、仅提出带不确定性的解释。快照证明落盘，不单独证明输入可见或心理依赖。

**评分边界：**锁定实际安装的 grader、题目 JSON、两份数据库和适配补丁哈希。仅针对 Q21/Q23/Q25/Q34 及控制题核验已记录的提交和候选值，不扩张成修复整个 benchmark。保留原二值反馈：不恢复官方答案反馈，不向 writer 暴露隐藏答案、参考 SQL、评分容差或另一方法的轨迹。

**交付：**`followup-records/d0-evidence.json`，每个结论含 source path/hash、事件/请求 ID、观察、未知项和路线决定。缺少本地完整状态包/请求时，报告具体缺口；不从最终快照补造题前状态，不把缺证据当作失败。

## 4. D1：Codex 纠错可达性——最多 8 个 solver 作业

只在 D0 确认 Q31 反例未进入 Q34 的主模型可见材料时执行；若已可见，跳过 D1，转入使用/写入解释，不做重复注入实验。

固定两个目标：**Q34（task-033，instance_id=107）**为风险案例；**Q28（task-027，instance_id=110）**为原先正确的不同主题控制。两题均按各自原始题前完整状态独立恢复，不能串行继承本轮分支产物。控制题只是目的性控制，不是代表性分布。

| 分支 | 条件 |
| --- | --- |
| R0 | 恢复目标题前原生记忆与共同配置；同期重跑，不用旧成绩替代 |
| R1 | R0＋最近三道已完成任务的原始证据侧栏 |

侧栏固定为同一方法的前 3 道题，按时间顺序复制 `prompt`、完整 `tools[].action/observation` 和最终 `feedback`；不带 assistant 的事后解释，不让 LLM 摘要，不按正确性筛选，不写“应该使用哪个字段”。Q34 的来源是 task-030/031/032；Q28 的来源是 task-024/025/026。所有来源严格早于目标。这个侧栏属于新的读取适配，不称为原生 Codex 默认行为。

两分支共同避免后台在目标求解过程中刷新前置记忆；保留原生读能力和业务工具，任何本题写入只留在隔离分支，不反馈给其他目标。确切开关和实际生效证据写入 lock。保持当前任务及原查询预算，不允许把多个 ANSWER 当作重复试答案。

**规模：**2 目标 × 2 分支 × 2 次独立执行＝8 个 solver 作业；一个作业可能含多个 API 请求。成对交错顺序，禁止失败重跑到成功。

**验收与决定：**先确认 R1 的侧栏确实进入主请求、R0 没有该额外侧栏、两组其余条件一致。报告 Q34 的选择及正确性、Q28 是否新增错误、查询数、全角色用量和侧栏成本。若两次配对在风险题都同向改善且控制题无新增错误，只能判为“值得保留的简单工程信号”；不能用 8 次作业声称稳定效果。若 R0 已稳定正确，或差别不稳定，结论为缺口未复现，不扩大整流重跑。

若简单侧栏有效，优先保留这种修复或随后单独评估确定性的增量暴露；不默认每题全量整合。若主请求已含反例却仍选错，不继续提高写入频率来掩盖使用问题。

## 5. D2：Claude 的纠错写入资格——最多 8 个维护作业

D0 完成后执行这项受控检查；它不以 D1 的胜负决定是否有意义。**首先看普通写入对照是否已经足够，不实现新记忆数据库或新反思 agent。**

固定两个写入事件：Q23（task-022）与 Q25（task-024）。各自从该事件原始 before 完整状态恢复，给出本次任务的完整合法业务轨迹和最终二值反馈，并允许查看本方法截至该事件的历史来源。Q23 不得看到 Q24/Q25；Q25 不得看到 Q26 及以后。两事件独立，不能把本轮 Q23 的候选写入拿去替换 Q25 的初始输入。

这是明确的**受控维护 fixture**，不是原始内部请求的逐字重放。优先复用选定 Claude 原生维护路径；共同入口只要求维护本次记忆、不得改业务提交或运行新的数据库查询。若必须改变入口/工具权限，先记录共同适配，不能把它只加到一个分支。

| 分支 | 条件 |
| --- | --- |
| W0 | 相同原生模型、维护工具、合法来源和共同维护入口，无新增证据约束 |
| W1 | W0＋下述通用约束；不新增正确字段、不增加来源、样例或调用额度 |

固定附加文本：

> 区分直接观察、候选解释与任务反馈。写入历史事实前核对可用来源；未记录不等于不存在，不得为了让新旧反馈一致而补造历史条件。一次 CORRECT/INCORRECT 可以改变解释的相对可信度，但不能在替代解释尚未被区分时，直接升级为普遍规则或已证实根因。记录本次实际测试了什么、未测试什么及适用范围；未知就保留未知，同时保留仍有来源支持的有用知识。

来源选择、目录索引与长度预算对 W0/W1 完全相同；不得把 Q21 DDL 只提供给 W1。实际请求若无法复核来源公平性，停止效果解释。

**规模：**2 事件 × 2 分支 × 2 次独立维护＝8 个维护作业；不等于 8 个 API 请求，不包含新业务解题。

评价的是有界主张，不使用“整份记忆 0/1/2 总分”：

- 是否仍断言 Q21 没有 `prc_v2`，或把“没在某个摘要记录”改写成环境不存在？
- 是否把 Q23 未计算的 `prc_v2` 候选写成已经测过/已被验证？
- 是否把 Q25 的单次接受写成排除了所有其他字段、确定了隐藏 grader 机制？不要求模型知道隐藏容差。
- 本次查询与接受/拒绝等直接事实是否保留，价格覆盖差异、对象范围等有用信息是否被正确保存？全部删光或全部写成未知不能算改进。

原始快照是历史观察，不代替同期 W0。语义核对只看新增/修改的主张与可定位来源；逐字匹配只能辅助。缺来源应标 unknown，而不是自动判错。二事件同属价格机制族，不算两个独立场景。

若 W0 已能忠实修正，不开发新算法。若 W1 明确改善且未抹去关键支持事实，先保留简单 writer 提示；不声称新颖性。若两者都失败，只有在输入充足且问题重复的前提下，才另立下一项方案；本计划不自动加入置信度系统、规则编译或更多框架。

## 6. D3：写得更谨慎是否有下游价值——条件性最多 8 个 solver 作业

仅在 D2 两次重复中 W1 都消除了已核实的历史事实错误/过强断言、未新增此类错误且保留关键支持事实时进入；若只能改善措辞，不自动执行 D3。

固定转移：**Q23 更新 → Q25；Q25 更新 → Q27**。每个 W0/W1 的两次产物都各使用一次，不择优选“最好看”的笔记。共 2 转移 × 2 分支 × 2 产物＝8 个 solver 作业。

目标会话从对应写入事件结束的候选状态启动，业务环境取目标的正确数据库版本。中间任务不执行，两臂均不导入其中的新记忆。这是明确跳过中间任务的局部分叉，不冒称原顺序流重放。目标自己的轨迹、反馈和官方参考仅留在评价端。

官方正确率/reward 与查询/token 并列；另报预登记的字段/计算解释诊断，并标明它仅对这个 benchmark 参考语义有效。一个输出处于容差内不证明解释学对；一个字段与参考 SQL 一致也不自动证明所有业务语义唯一确定。若质量靠退回全面探索换来，要如实报告，不称全面增益。

写入更忠实却未改善目标行为/成本，可交付记忆质量工程结论；没有理由自动重跑 40×6。后续正式方法研究、完整在线验证和独立环境需要另定范围。

## 7. 共同约束、成本与停止

沿用已验收的 GLM、相同 provider 和框架版本，不在本轮又更新到 latest。原求解 high；总窗口 262,144、输出上限 65,536、压缩目标 196,608；辅助 effort 沿用并记录。最终以本地本轮 lock 核实，不把这些研究参数当作所有 CLI 通用字段。原 provider 不可用时，两臂统一新入口并同期重建参照，不能仅更换候选端。

每个独立分支使用相同合法前缀、数据库哈希、工具权限、最终反馈协议和任务预算。参考 SQL、未来题、其他方法的经验、LLM judge 材料与整个导出目录都不挂载。维护仅允许写隔离记忆区，不允许扩大外层授权或碰真实凭据。

本计划的最大范围为 **16 个 solver＋8 个维护＝24 个原生作业**，有前置跳过条件，不默认跑满。它不是 API 次数或金额上限。每阶段冻结实际版本/输入/预算和付费执行范围后由本地执行；本次文档提交不自动调用模型，也不沿用旧批次的无限授权。

HTTP 失败、重试、缺 usage、原生维护/子 agent、压缩与被拒绝写入均留痕并计费。保持既有可恢复传输政策，不因正常答错重跑。脱敏公开汇总，正文与 key 留在隔离私有区；未知费用不填零，不用旧价目宣布实际金额节省。

**立即停止该阶段的条件：**来源/权限不公平；只有最终快照无法恢复前置状态；题目缺少可识别证据却要求猜隐藏约定；简单对照已经足够；差异仅为评分容差；收益靠更多计算且没有明确成本主张；效果未复现。停止不等于否定全部 agent memory。
