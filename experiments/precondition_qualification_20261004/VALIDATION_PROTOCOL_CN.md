# 下一轮：先找缺口，再实现候选方法

状态：研究协议，真实模型验证未执行；非付费运行授权。本文件不修改已有实验阶段、预算或停止规则。仓库同步后的具体命令与验收见 [实验指南](实验指南.md)。

## 1. 先通过事故资格关

选取至少两类相互独立的工作事故，不用同一类 SQL 关联换文件名凑两类。每类必须能给出：合法任务、关键动作前的状态、历史失败、实际反馈、有效修复以及一个表面相似但原规则不应生效的合法情况。

资格记录可采用：

```text
incident_id / family_id:
原始记录位置与可读范围:
当时任务和用户要求:
动作前可观测状态:
发生过的操作、错误与合法反馈:
修复方式和验证结果:
后来哪些条件改变会使原结论不适用:
当前状态是否已足够，无需历史:
是否存在现成配置、库选项、启动检查就能解决:
独立评价器如何检查结果:
没有足够证据时，允许怎样进一步核验:
```

真实凭据事故可作为一个工程例子，但只能使用脱敏信息和假凭据；用模拟账户替代真实身份。已知“密文绑定账户”的限制可直接配置，不足以单独证明需要学习。原始会话未可访问时，复盘报告只能证明报告中的事实，不能伪造原始可见状态。

以下情形不进入效果比较：隐藏业务要求没有向 agent 提供且无法查到；两个可见输入完全相同却要求相反决策；只有模型主观评分；测试调用了参考实现而非提交；已知简单检查已稳定解决而没有成本上的研究目标。

## 2. 最便宜的模型资格筛查：动作判定而非全流程

每类先选 4 个动作前快照：

1. 原类错误重复：关键前提仍然不满足。
2. 正常执行：相关前提满足。
3. 合法近邻：动作相似，但任务目标不同，旧的禁令不应生效。
4. 作用域变化：项目、数据口径或明确授权范围改变；正确决定由真实可见资料支持，而非刻意隐藏规则。

这些是控制性变体，不能称为自然工作分布。原事故和反例选择在看到新方法结果前冻结。第一轮可只筛两类，共 8 个状态，不必建设新 benchmark。

三种模型输入条件：

| 组 | 输入 | 回答什么 |
|---|---|---|
| A current | 当前任务、当前合法状态、待执行动作 | 不用记忆是否已经能解决 |
| B history | A + 相关的完整合法历史 | 去掉检索瓶颈后，经验是否有用 |
| C preflight | B + 通用的适用性核验提示 | 简单提示是否已经解决 |

B/C 的来源一致。C 提示不能加入 evaluator 才知道的业务结论。A 仍保留当前合法业务文件、状态和工具权限，不应故意制造失明的 No Memory。

建议上限：2 类 × 4 状态 × 3 组 × 2 次独立请求 = **48 次判定调用**。它们不是 48 个完整 agent 任务，不测在线持续学习。两次重复只是筛查稳定偶发错误，不能据此宣称统计显著或零风险。

仓库版本使用 `qualification.py init/check/prepare/run/accept` 管理模板、人工签认、三组交错请求和汇总。正式入口冻结 8 条案例、A/B/C 和两次重复，共 48 次判定。完整命令、单次接口 smoke 和预算见 [实验指南](实验指南.md)。默认生成请求；只有显式 `--execute` 才调用模型。

私有真值按组登记：A 信息确实不足时允许 `inspect`，但不把它算业务完成；B/C 信息一致，首批要求足以判定 allow/block。真正需要继续查证的 B/C 状态另立协议，不强行赋二元标签。公开输入不含原因类别、正确规则、反例类型或参考解。

## 3. 根据筛查结果选择，不预设一定进入新方法

| 观察 | 决策 |
|---|---|
| A 已能稳定判对，B/C 没有进一步价值 | 停止以这些案例支持“必须依赖历史”；保留为普通检查回归任务 |
| A 差、B 好 | 先解决经验交付；未证明前提归纳方法必要 |
| B 差、C 好 | 通用 preflight 是有效简单参照；不要先建复杂规则治理 |
| C 仍犯相同条件错误，相关证据可见，且至少两类事故有迹可查 | 才进入有限的自动检查生成验证 |
| C 判定正确，但原 agent 不执行检查 | 瓶颈是挂接/执行；给简单检查器相同工具边界，再评估，不归因于学习 |
| 简单检查正确但每次推理昂贵 | 可另立“规则编译摊销成本”工程假设，不能把它称为新归纳算法 |
| 人工正确规则都不能据合法状态区分正反例 | 优先修观察/任务定义，不开始模型学习比较 |

不将一个 inspect 记作一次成功阻拦；还需要可接受的额外核验和合法任务完成。始终全部 block 或全部 inspect 不应获得高分。

## 4. 必须接着验证“动作判对”能否成为真实行为

判定筛查通过，只是进入端到端最小执行的资格。复用同样事故的可恢复环境，以原业务任务成功、已知坏效果是否真实发生、合法任务是否误阻、总成本为结果。

要记录：规则是否生成 → 可执行否 → 能否获取所需状态 → 是否在相关动作前被调用 → 如何处理拦截 → 后续能否完成任务。每一步都不能用上一层通过代替。

禁止在真实数据库、真实密钥、不可逆写入上自动试错。候选代码在隔离沙箱执行，只读状态、限定工具、无网络和凭据访问；必要操作在快照副本上验证。保持已有授权检查为外层不可修改约束，学出的规则不能扩大权限。

## 5. 只有缺口成立，再比较一次生成与反例验证

G0：模型看相同自然历史，一次生成检查，无特殊准入系统。

G1：相同起点，但经过有限反例核验才提交检查。

为了不把更多样例/计算当成算法效果，还要让简单 G0 有一个相同新增证据/调用预算的版本。若给定了人工特征表，应加入简单规则学习；若不提供特征，不能声称胜过只能接收结构化特征的 STAND，而不解释信息接口差异。

历史只提供自然可见反馈，不能从隐藏评分中提取正确前提。反例标签需要环境、任务契约、用户澄清或独立 verifier 支持，不采用“同一个模型同时出题、判答案、宣布通过”的自证闭环。

留出至少一组作用域/合法例外变化，在生成规则和反例时不可见。换数字/路径的同模板变体只叫受控检查，不叫新机制泛化。

## 6. 主指标、成本和停止

错误复发和合法任务完成并报；false block、遗漏坏操作、inspect/用户中断、完成率、失败/未知 usage 都单独统计。测试次数不是现实风险概率，不用几十个合成例子证明“安全保证”。

成本分别列：规则生成、检查/反例、修订、后续调用的提取与运行、业务执行、外部评分。正确性相近时才有意义比较摊销：

```text
生成 + 验证 + 维护 + N ×（运行时状态提取 + guard）
    对比
N × 普通 preflight
```

实际业务执行和错误恢复成本也并列，不能假定它们在两组相同。无实际价格或账单，不报告金额优势。规则可能过期，其修改频率也要计入，不能假定一次生成永久使用。

初筛不预设“必须提升 X%”的统计结论；运行前登记可接受误拦、成本和进入下一步的标准。若简单替代足够、缺口只有一个不可复现个例、评分无法支持主张或外部研究已完整覆盖具体改动，则停止方法扩张。不要通过继续加异常类型，事后制造只能让新方法取胜的分布。

**本轮终点应该是一张真实简单对照的资格表，而不是一个新的多模块系统。**
