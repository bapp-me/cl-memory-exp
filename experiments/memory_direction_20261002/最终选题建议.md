# 三个 training-free Agent 方向：选题结论与证据

2026-10-02。小规模选题验证完成，推荐下面三个方向。优先选择方向一；方向三适合做成本与质量对照鲜明的系统项目；方向二更偏 Agent 工具协议与可靠性工程。确认范围是“问题已复现、存在可行改进空间、值得开展项目”，泛化收益和论文新颖性尚未得到证明。

实验使用用户提供的 GLM-5.3-Flash、DeepSeek-V4.1-Flash API，执行器为 Claude Code 2.1.286 和固定源码的 Hermes。没有训练模型。实验材料、失败与反证保留在阶段 01–03 文档、逐次运行目录及汇总表中；本文件是补完强基线后的最终判断。

|方向|独立问题|最有说服力的证据|项目价值与边界|
|---|---|---|---|
|一：带适用条件的经验复用|记忆已读到，但过去有效的经验被扩大到不适用的任务|CL-Bench 的价格列覆盖问题；两模型的具体条件修订均能答对|最接近用户最初的 a/b/c 设想；应自动提取、验证适用条件|
|二：检索完整性与可靠回退|真相在原始记忆里，但返回被截断，Agent 错称“没有更新”|MAB 多步问题与另一条单步问题复现；保留时间戳的原子索引、原生文件回退均有效|工程价值明确；已有文件工具是强基线，当前不支持重做一套向量检索器|
|三：记忆写入的收益与计算预算|原始资料已可检索，Agent 仍花很多 token 反复整理，且会写入过期事实|同一旧记忆和工具下，默认整理 33,192 输出 token，最小索引 596；配对后续题均答对|适合做写入粒度、推理预算和长期总成本的控制；索引方案依赖原文持续可访问|

这三个问题分别对应知识的适用性、证据的可见性、写入的经济性。方向一在完整记忆已经进入上下文时仍可能发生；方向二在没有生成式整理记忆时也复现；方向三在两组使用相同完整读取工具且答案均正确时仍有成本差距。因此不是同一故障换三个名字。

## 一、带适用条件的经验复用

**具体问题。** a 是低价电子商品的评论统计。Agent 观察到 `prc` 为美分、`prc_usd` 为美元，在共同非空行上数值一致，然后写入可复用知识。后续任务 b 能复用表结构、连接键等发现；c 要求全部电子商品的均价，此时美元列缺少 224 件高价商品，直接沿用会产生偏差。

源数据库可独立复算：`prc` 有 6,570 个值，`prc_usd` 有 6,346 个值。完整均价是 **96.233449**，不完整列的均价是 **52.956662**。正常入口下，DeepSeek 写出的源记忆把共同非空行的等价推广为任意价格阈值都等价；GLM 记下了覆盖差异，但没有把它变成后续使用条件。

|Claude Code／Q9|数值答案结果|
|---|---|
|DeepSeek，无跨任务记忆|2/3 正确|
|DeepSeek，原始原生记忆|1/3 正确|
|DeepSeek，补明确覆盖条件|2/2 正确|
|DeepSeek，仅增加泛化的“核验假设”提醒|1/1 正确|
|GLM，原始记忆／无记忆|各一次，均错误|
|GLM，仅修订自己生成的源记忆的覆盖条件|1/1 正确|

修订只使用 a 已观察到的非空计数和单位关系，不含 c 的答案。样本不足以估计稳定负迁移概率，也没有证明具体条件一定优于泛化提醒。强消费者可以恢复：Hermes + DeepSeek 在有原生记忆的 Q9 答对，而无记忆那次答错。

**为什么仍值得做。** 泛化提醒能纠错，但可能增加不必要的探索。在 b（Q12）中，同为正确数值答案，原始记忆用了 6 次 SQL，增加核验提醒用了 13 次，无记忆用了 30 次。这是一次成本对照，不是稳定加速比。项目目标应是“需要时验证、已证实适用时复用”，而不是把每次任务都重新探索一遍。

首次建记忆费用也有记录：把整个 a 的费用都保守计入开销，再加两个已测后续任务 Q12/Q5，峰时单价估算为 $0.017662；仅这两个后续任务的无记忆对照为 $0.023658。它支持实际复用收益的可行性，但 API 缓存采用真实返回状态，不是清空缓存后的实验，也不是稳定连续任务流收益估计。

**理论和方法入口。** 对目标总体 P 替换两个字段，至少要同时验证数值关系与非空覆盖：`values_equal(P)` 和 `defined_rows_equal(P)`。过去在子集上成立，不能直接推广到新的总体。[BASM](https://arxiv.org/html/2608.22339v1) 把技能的适用条件与执行步骤分开，可作为相邻方法基线；本实验没有复现它的注意力或 logit 机制。

值得实现的训练无关机制是：写入时保存 claim、证据、已验证范围和可执行检查；读取时根据当前任务决定直接复用、局部验证或拒绝。必须保留无记忆、原始原生记忆、泛化提醒、人工有效域四种基线。主要指标为答案、错误复用率、额外工具调用和包含写入的总成本。当前没有证据要求先做复杂检索或训练一个判断器。

## 二、检索完整性与可靠回退

**具体问题。** MemoryAgentBench 的合成池有 455 条带 serial 的事实；更大 serial 覆盖同主体、同关系的旧值。三步问题的正确链为 146 → 335 → 322，答案 Belgium。原生历史检索只让模型看到了旧作者 107，漏掉同一长消息里的更新 146，模型最后回答 United Kingdom，并声称“没有更新”。

提高输出上限到 32,768 后，纯历史和“整理记忆 + 历史”都出现这个错误。工具返回含 `content_truncated`，原始数据库中的更新仍存在。额外检查一条官方单步问题后，也出现旧值 Asia 被当作最新值，而合成池 serial 234 已把它改为 Oceania。此单步题是根据已发现的机制定向选择的诊断，不代表随机样本准确率。

|对照|结果|
|---|---|
|三步题，原生历史的第二次运行|错误 United Kingdom|
|三步题，带整理记忆的两次运行|均错误 United Kingdom|
|三步题，逐事实索引且保留原始父会话时间戳|正确 Belgium|
|三步题，提供完整归档并启用原生 read_file/search_files|正确 Belgium|
|单步题，原生历史|错误 Asia|
|单步题，原生文件回退|正确 Oceania|

还保留了纯历史第一次答对三步题的反证。前期逐事实诊断改变过时间戳，后来已补保持父时间戳的对照。原生文件后端首次未找到主机非默认位置的 Git Bash，属于配置失败，已经排除；修好后先用无模型调用验证读、搜、路径拒绝，再重跑。

**项目边界。** 现成文件工具已经解决这些例子，选题应聚焦“如何知道当前返回不足，以及何时升级读取”。可以给结果附上覆盖范围、截断标记、原始来源与分页位置；遇到不完整证据时请求下一段、执行精确查找或回退到原始来源。在证据仍不充分时，避免把未检索到说成不存在。

若完整相关事实集合是 G，返回集合是 R，那么只对 R 取最大 serial，不保证得到 G 的最新值。[确定性冲突消解工作](https://arxiv.org/html/2606.01435v1) 提供了版本聚合与逐跳解析的强基线；我们的观测强调聚合之前必须让相关更新可见。现有原子索引、完整原文、原生文件回退都必须作为对照。

这是三个方向中工程属性最强的一项。实验覆盖受控的 Hermes 原生核心；不能据此声称所有 Hermes 配置或其他框架都失败。下一阶段应比较自动回退与“始终读原文”的成本和稳定性，而不是把此次工具问题包装为通用算法突破。

## 三、记忆写入的收益与计算预算

**具体问题。** 一份完整可检索的原文，不一定需要再次用模型压缩成热记忆。强制写入后，未限制整理形式的基线试图把任意事实压进 2,200 字符，消耗大量输出 token。增加输出上限后仍然昂贵；开放原生文件工具后也仍然昂贵。

下面是严格匹配的一次增量更新：三个条件起始记忆内容完全相同，同一个 DeepSeek 模型、同一新资料、同一归档与文件工具、同一 32,768 输出上限。只改变写入策略或写入 effort；读取阶段均使用 high。所有条件均要求持久化，这组实验验证的是写入形态和计算预算，未测试 Agent 自发决定是否写入的触发策略。

|写入条件|写入输出 token|写入时间|更新 + 两题总时间|两题结果|更新 + 两题费用估算，峰时 USD|
|---|---:|---:|---:|---|---:|
|自由整理，high|33,192|151.113 秒|188.446 秒|2/2 正确|0.060685|
|自由整理，low|8,535|41.720 秒|86.731 秒|2/2 正确|0.025881|
|只写最小索引，high|596|5.915 秒|30.272 秒|2/2 正确|0.014015|

最小索引只保留池的身份、serial 范围、更新规则和原文位置，没有塞入未来题目或答案。另一条从第一块就采用索引的独立写入链，在预先选定的五道后续题中为 5/5 正确。这个五题结果不是上表三组都跑了五题；上表的匹配对照是两题。表中排除了各组共同的旧记忆构建费用，属于从相同既有状态出发的增量总成本。

还查到自由整理的 high 条件确实写错一处：它声称保存最新值，却写入 `midfielder → association football`，原文 serial 416 已更新为 `sumo`。这只是逐字段发现的反例，没有据此估计整个记忆的错误率，也没有声称某个未测试问题必然答错。

**理论和方法入口。** [MemGPT](https://arxiv.org/abs/2310.08560) 的分层记忆提供了现成起点。这里可用的决策目标是：预期未来少付出的读取成本，是否超过当前写入、维护和可能失真的代价。把 `写入成本 + 读取成本 + 错误损失` 一起优化，比只追求摘要更短更合适。这是拟议的决策目标，不是已经证明的最优策略。

值得做的策略选择包括：完整原文直接进入上下文、仅建立索引、保存少量结构化事实、进行较重整理，以及分阶段设置推理预算。须与 always-index、always-curate、低 effort、纯长上下文及缓存基线比较。6k 原文直接放入上下文本身就很强，应纳入选项。索引方案的前提是原文持续可访问；本实验没有证明在原文失效或长期高频重复读取时它仍最优。

DeepSeek 官方文档确认 `output_config.effort` 生效，`thinking.budget_tokens` 被忽略，high 是默认强度。因此我们用 low 做了实际对照，不把忽略的预算字段当成有效限额。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Anthropic 兼容说明](https://api-docs.deepseek.com/guides/anthropic_api/)

## 已降级、排除或限制的结论

- 简单旧值更新：三个 LongMemEval 短案例全部正确，目前不足以单独立项。
- “换 Agent 结果都一样”：不成立；Hermes 的原生记忆在均价任务中帮助它恢复正确。
- “具体条件一定胜过泛化提醒”：尚未证明；泛化提醒也能答对，额外探索成本值得进一步研究。
- “要重新做向量检索器”：没有依据；完整文件读取、精确搜索和原子索引已经是有效强基线。
- 单次 8k 输出耗尽、24 请求保护、缺失 Git Bash：属于预算／配置因素，费用保留，不能混作记忆逻辑失败。
- 初始 restricted 入口、遗漏共同题意、答案解析错误、时间戳偏移：修复及历史结果均有记录；主结论使用有效协议。
- BASM 完整算法、注意力机制、模型排名：未复现。它用于方向一的理论与方法对照，不计作第四个成功方向。

## 复核与交付

`results/selection-evidence.json` 逐项保留源数据复算、相同旧记忆校验、返回可见性检查、完整时间戳对照、写入与读取总费用。`build_selection_evidence.py` 可重新核对这些具体观察；它不把断言通过当成泛化或新颖性证明。

全部运行的 prompt、参数、模型响应、工具结果与记忆前后快照位于 `results/runs`；HTTP 记录无损 gzip 并附哈希清单。数字汇总为 `results/run-scoreboard.json`、`results/text-memory-scoreboard.json`、`results/usage-report.json`。模型原生的第三方价格估计未用作实际账单，费用按逐请求 token 统计；一次流中断存在未知输出，因此金额仍是估算。GLM 未取得可靠的适用单价，提供完整 token 用量。

完整新增软件、依赖版本和保留的环境代际见 [安装清单](安装清单.md)。建议以方向一作为主项目，方向三作为第二选择；方向二可以独立做可靠性工程，也可成为前两个项目的基础模块。

截至最终检查点，共有 97 份运行记录（含诊断、失败和对照），成功计量请求仅使用两种指定模型。DeepSeek 记录为 863,343 未缓存输入、6,209,024 缓存输入、459,900 输出 token；计入那次中断最多还可能产生的 8,192 输出 token 后，按官方峰谷单价保守估算约 **$0.424–$0.858**，不是账户账单。GLM 记录为 98,451 未缓存输入、356,480 缓存输入、24,642 输出 token。1416 个压缩 HTTP 文件已逐一验证解压后字节数与 SHA256。
