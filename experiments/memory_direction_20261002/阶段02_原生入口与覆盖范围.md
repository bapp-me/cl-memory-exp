# 阶段 02：原生入口、覆盖范围与反证

日期：2026-10-02。此阶段保留 Claude Code 正常入口和会话持久化，固定模型，继续使用阶段 01 冻结的 CL-Bench 数据。结果仍是方向初筛，不能解释成统计显著的产品排名。

## 接入修正

阶段 01 的 restricted 入口虽然允许读文件，但首次请求没有原生记忆索引，不能代表完整 auto-memory。现在移除 restricted、保留原生会话入口，每次使用独立 home/workspace。通过 PreToolUse 将文件工具限于实验工作区，SQL 仍只能通过只读接口访问。凭据和 gold 不在可读范围内。

`diag-native-capture-01` 在本地截获首次请求，不发给付费上游；原生索引内容实际进入请求。真实运行同时记录初始上下文及 Read 调用。正常入口的 a 后仍明确要求写入记忆；后续自主选择是否读取详情。不能把“索引在上下文中”“调用 Read”“决策被记忆改变”视为同一件事。

## 首先保留反证

正常入口下，DeepSeek 和 GLM 写出的价格单位知识都限定到 g2；阶段 01 中的跨表单位泛化没有在这两份新记忆重现。强消费者也能自行纠正误导：DeepSeek 均价第二次有记忆答对、无记忆反而答错。不能挑第一组成功制造负迁移故事。

## 一个可执行的适用条件

电子商品有两个价格列：`prc` 为美分，6,570 行有值；`prc_usd` 为美元，仅 6,346 行有值。二者在共同非空行上数值等价，但 224 件高价商品缺少美元列。完整均价为 96.233449 美元，直接平均美元列为 52.956662 美元。零价格在此快照中不存在，因此 Q9 的差异不是零值口径造成的。

a（Q11）的低价筛选没有暴露这项覆盖差异。DeepSeek 的源记忆同时记下两个列的非空计数，却进一步断言任意美元阈值的两种写法都得到相同行集。GLM 的源记忆记录了 224 行缺失模式不一致，但没有解释其对后续统计的影响。这些记忆由真实 a 运行生成，未手工加入错误。

对于替换列 f/g，只有数值相等还不够；在目标筛选条件 P 下，还需要验证两列的可用行集合一致。a 中成立的条件并不推出另一种任务下也成立。这给“环境经验保存有效域、证据和验证条件”提供了一个具体接口，而不是笼统要求模型更加小心。

Q9 第三次 DeepSeek 有记忆运行发现了 224 行和两种均价，仍选择报告不完整美元列。该轨迹不能简单归类为“没有检索到正确证据”。

## 简单对照与剩余价值

`fixtures/coverage-diagnostic` 只改写 DeepSeek 源记忆中的过度泛化句：明确等价仅在共同非空行成立、两列覆盖不同、按目标总体选择价格列后再换算。所需计数已在源记忆中，不添加目标答案。索引保持不变。

首次诊断中，DeepSeek 和 GLM 都得到正确 96.23。DeepSeek 为同一源记忆的手工修订消融；GLM 此次使用的是修订后的 DeepSeek 记忆，属于跨模型手册对照，不能与 GLM 自己的源记忆当作严格单变量消融。

这表明简单、具体的适用条件值得作为强基线。当前没有证据支持复杂检索器优于这条简单基线，也没有实现自动优化。剩余研究问题是：能否从原始观察自动构造、维护这些条件，并仅在任务超出已验证范围时付出检查成本？BASM 将经验适用性与语义相关性区分开，可作为相邻方法基线；我们的本地结果不构成其复现，也没有 API 模型的注意力或 logit 证据。[BASM 原论文](https://arxiv.org/html/2608.22339v1)

当前该方向升级为“值得继续”。最终确认仍等待简单对照重复、原生多 Agent 覆盖和成本核算；其余方向尚未取得足够证据。
