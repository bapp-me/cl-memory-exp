## 具体复核

1. `build_selection_evidence.py` 直接重算价格总体及缺失列均值，确认修订记忆不包含目标答案；核对目标运行的实际最终响应。
2. 原子检索的 455 条事实逐条与父块比较，保留对应时间戳。错误轨迹的工具返回中确实缺少 serial 146／234；正确原文中确实存在。
3. 三种增量写入策略的初始记忆内容哈希相同，模型、历史、文件工具和输出上限相同。每组两个读回题均正确；计量读取所有 HTTP 请求，不只取 Agent 最终 usage。
4. 写入高 effort 后的 `midfielder → association football` 与同批原文 serial 416 的 `sumo` 不一致。它是一个实测写入错误，不是推测下游一定会错。
5. 原生文件后端的无模型检查验证了读、搜和越界拒绝；只读 SQL 检查验证写入与 ATTACH 拒绝。数据库最终哈希与开始时相同。
6. `.private` 被 Git 忽略；对交付文件和 gzip 内文扫描实际密钥，未发现密钥。凭据只在私有加密配置与调用进程中使用。
7. 所有已发起的模型运行均已返回终态，原始 summary、失败原因和费用记录保留。没有以观察超时为由重复启动同一个 run_id。

最终文件检查：97 个运行目录均有 summary，process 状态无未结束记录；成功记录的模型集合恰为 `deepseek-flash`、`glm-5.3-flash`；1416 个 HTTP 压缩文件的哈希与长度校验通过。结果见 `results/final-artifact-checks.json`。检查点扫描没有发现实际密钥，SQL 数据库哈希未变。

## 不属于已证明的结论

没有证明统计显著的整体提升、跨所有任务和所有 Agent 的泛化、三个新的论文算法，或长期生产环境收益。选题建议明确包含工程定位、强基线和下一阶段的评测要求。用户本轮目标是判断方向是否值得做，因此这些后续开发／研究问题不伪装成已完成成果。
