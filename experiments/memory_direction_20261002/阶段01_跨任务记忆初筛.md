# 阶段 01 跨任务记忆初筛

日期：2026-10-02。状态：**已完成第一组双模型小样本，发现可重复的写入范围错误；尚未确定最终三个值得做的方向。**

## 已执行的环境与协议

- 执行器：隔离安装的 Claude Code 2.1.286，保留其决策循环；统一开放 SQL MCP 与文件读写工具。`--restricted` 限制文件访问，gold 和密钥不进入 Agent 可读目录。
- 后端：GLM-5.3-Flash、DeepSeek-V4.1-Flash（官方 API 名 `deepseek-flash`）。接入层显式发送 thinking enabled、effort high，所有请求和返回用量可核查；供应商兼容接口未报告独立 thinking token，不能据此断言没有思考。
- 数据：CL-Bench 固定题目提交 `5f8c50e...`，数据库 397,910,016 字节；文件 hash 与固定 Hugging Face LFS hash 一致。30 条 gold SQL 全部重算匹配，Q2/Q11/Q12 又以不同 SQL 结构交叉核验。
- 主三元组：a=Q11，b=Q12，c=Q2。完成 a 后强制写入环境记忆与索引；b 对比无经验、自主读文件；c 对比无经验、直接提供 a 的完整记忆。两个模型分别生成自己的记忆。
- b/c 均为隔离新会话，从同一份 a 后文件状态分别启动，没有相互污染。
- 这是衍生协议，不使用原 benchmark 的 15 QUERY regret 分数。完整差异、初始失效试验和修正原因见 [协议修正记录](results/协议修正记录.md)。

**重要命名修正：**脚本内部及部分运行 ID 的 `native` 只是历史标签。实际请求审计未发现 auto-memory 索引自动注入；这组依靠模型在获得“有可用经验”的提示后自主 Read 文件，不能称为已验证的 Claude Code 原生 auto-memory 系统。两个模型都有实际 Read 记录。当前实验验证的是强模型在成熟 Agent 中消费跨任务文件经验的行为。

记录：[逐运行评分与读取证据](results/run-scoreboard.json)。SQL 次数包含探索、验证及计算，不能全部称作冗余探索；运行并发和缓存状态也会影响秒数。完整构建成本还没有与无写入源任务做增量配对，因此这里**不声称端到端已经回本**。

得到的有限结论：

1. 两个模型在 b 上都实际使用经验，并在本次运行中减少查询，值得继续查其稳定性与简单手册对照。
2. c 没有出现期望中的错误答案负迁移。DeepSeek 的直接提供组多了 3 次查询，但只有单次配对，尚不能把时间或查询差全部归因为错误记忆。
3. GLM 的 c 反而更接近预期口径。原数值 checker 对两者都可能通过；不能宣传为官方榜单上的错误→正确。

## 真实复现的写入缺陷

我们没有给模型错误记忆，也没有删掉范围来制造失败。a 的写入提示明确要求记录范围、证据和推测状态，但仍出现了以下自然生成错误：

|运行|记忆中的错误|如何核验|
|---|---|---|
|DeepSeek Q11 写入 r1|将 g2 的美分编码推广到 g1/g3，放在 VERIFIED 价格说明中|g1 的价格过滤应为 `prc > 50`；误用 `>5000` 后评论均值从 4.1054 变为 5.0|
|DeepSeek Q11 独立写入 r2|再次把 `prc` 描述为 g1/g2/g3 都使用美分；该次放在 inference 段落中|同上；说明简单要求区分推测和验证并没有消除内容错误|
|DeepSeek Q10 写入 r1|将 `fdbk_g1.ts` 写成 epoch seconds；正确格式是 milliseconds|Q1 正确格式得到 58；若按这条错误事实直接查询则得到 377,472|

原文、行号与 SQL 反事实见 [记忆事实审计](results/memory-claims-audit.json)。三个写入结果来自两个源任务，是小样本复现，不是错误发生率统计。

DeepSeek 的 c 读到了第一条错误记忆后，明确重新验证 g1 的价格单位并答对。这说明**写入缺陷确实存在，但强消费者可能恢复**。SQL 反事实只能说明错误事实有潜在危害，不能替代自然下游退步证据。

GLM 第一次有效 Q11 记忆正确限定了 g2 单位，因此不能把 DeepSeek 的问题外推为所有模型必然发生。

## 暂时不成立的主张

- 不成立：已经发现三条值得做的方向。
- 尚无证据：强 Agent 在 c 上会稳定受错误记忆影响而答错。
- 尚无证据：某个新系统优于原生自动记忆、简单事实手册或完整可用历史。
- 不能使用：遗漏原始题目背景的 debug-v0 运行，或 Claude 对第三方模型的未知费用估计。
- 不能使用：只选成功写入或检索成功的运行，隐藏失败后当端到端成绩。

## 下一步实验

先围绕当前观察缩小因果问题：保留原始自然记忆，与只纠正范围或删除未验证断言的诊断副本配对，检查错误是否增加恢复成本或造成结果退步。诊断副本不是新优化算法，也不作为自然产生的记忆成绩。

然后扩展时间格式任务族。Q10 源任务已完成并生成错误的跨表时间单位说明。Q23 的异常时间戳存在“按固定单位看是未来日期”与“解释为误存毫秒”两种解释风险，须先审题，不直接拿其 gold 差异证明模型失败。可优先使用日期窗口计数的明确衍生题或已核验的其他原题。

同时补真正原生记忆入口验证和简单手册对照。若范围校验只是当前提示改写即可解决，或强消费者低成本恢复，则应收缩方向价值，不为凑数夸大。
