# 协议修正记录

2026-10-02：初始 smoke test 和 `ds-a11-write-r1`、`glm-a11-write-r1`、`ds-b12-none-r1`、`ds-b12-native-r1` 属于接入调试，不纳入记忆效果主比较。

原因：初始通用数据库提示遗漏了原 CL-Bench `QUESTION_TEMPLATE` 中“三个独立数据集，分别涵盖 Office Products、Electronics、Musical Instruments，每组有自己的表”的共同背景。GLM 将 electronics 理解为跨组 `main_cat='All Electronics'`，生成 15.52%，而原题的完整背景对应 g2 全组、gold 10.22%。DeepSeek 虽答出原 gold，也进行了额外口径检查。因此初始组间差异混入了不完整题意，不能用来声称记忆修复了模型缺陷。

修正：`clbench-derived-v1` 恢复原始共同背景，仍不泄露 g1/g2/g3 映射、价格单位、gold 或知识标签；工具结果上限恢复为 50 行。所有有效配对重新生成 a 的记忆，保持同一协议。

仍与原版不同的部分：采用 Claude Code 的原生决策循环和 MCP SQL 接口；最终输出附计算 SQL；源任务后强制保存真实观察；不提供 gold 反馈；每次新会话、记忆快照分叉；API 请求上限为节费保护，不使用原版 15 QUERY 的 regret 分数。正确率、全部查询与成本分开报告。

原始提示来源：<https://github.com/pgasawa/continual-learning-bench/blob/5f8c50eb1e84b2eda2ef4faff757dfc812a0ea26/src/tasks/database_exploration/prompts.py>。

另外，Claude Code 将这两个第三方模型的 `costBasis` 报为 `unknown`，其 `total_cost_usd` 不能作实际账单。按官方单价与供应商 token 字段另行估算，保留上下限；无法核定者只报 token，不伪造费用。

## 自主读文件组的命名

实际请求审计发现，当前 `--restricted`、第三方模型、headless 组合下，即使配置了 auto memory，首次请求并未出现 MEMORY 索引或 auto-memory 指导。设置文件中的开关不能证明功能生效。运行 ID 中历史命名为 `native` 的组，实际是“提示有可用经验，但由模型自主决定读文件”；DeepSeek 和 GLM 都实际调用了 Read。不得将该组称为已验证的 Claude Code 原生 auto-memory 基线。后续必须补正常入口的原生能力验证，或持续用准确的“自主读文件”标签。

## 精度与口径

Q2 原 gold 为 4.11，原 checker 的浮点容差至少为 1%，因此 4.1282 可能也获官方数值判分通过。主记录同时保留严格按 gold 两位精度比较、原版数值容差比较及最终 SQL 输出。是否误加 `main_cat` 过滤需要结合题意审计，不把这一条的严格判分变化夸大为原榜单上的成功率提升。
