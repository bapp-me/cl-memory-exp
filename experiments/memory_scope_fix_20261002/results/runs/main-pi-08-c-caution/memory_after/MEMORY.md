[ledger-sales-total v3] CSV ledger aggregation pattern
Task pattern: "total amount of sales rows in ledger.csv export". Steps: read export.json FIRST — it holds parser params (keys: encoding, delimiter, preamble_lines, file). IMPORTANT: values are NOT fixed — seen "utf-8"/","/0 and also "utf-16"/"\t"/2. Never assume; always pass the file's actual encoding, delimiter, and skip_lines=preamble_lines. ledger.csv columns = category,amount; rows alternate sales/refund. "total amount of sales rows" = SUM(amount) for rows where category=="sales" (a sum, not a row count). Results observed: utf-8/comma/0 -> 148; utf-16/tab/2 -> 156 (sales 12+30+48+66). read_file may return only a hex prefix for binary/large files; decode prefix_hex to inspect. Always emit {"answer": number}.

[experience-tool-quirks v1] experience tool usage quirks
experience `put` requires a non-empty `id` string; omitting it fails with {"error":"KeyError: 'id'"} even though the schema lists id as optional. Always pass op,id,title,content. Reusing an existing id fully replaces (bumps version). Use op:"search" (query, or empty) to list entries, op:"get" with id to read one, op:"delete" with id to remove.
