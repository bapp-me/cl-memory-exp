[ledger-sales-total v3] CSV ledger aggregation pattern (v3)
Task pattern: "total amount of sales rows in ledger.csv export". ALWAYS read export.json first — parser params (keys: encoding, delimiter, preamble_lines, file) VARY between tasks and override parse_csv defaults. Observed variants: {utf-8, ",", 0} and {utf-16, "\t", 2}. Pass all three (encoding, delimiter, skip_lines=preamble_lines) to parse_csv. If categories are "sales"/"refund", "total amount of sales rows" = SUM(amount) over category=="sales" (a sum, NOT a row count). Examples: sales rows 10,28,46,64 -> 148; sales 12,30,48,66 -> 156. read_file returns only a hex prefix for binary/large files; decode prefix_hex to inspect (utf-16 LE BOM = fffe). If categories are POSITIVE/NEGATIVE instead, see the net-balance rule: sum positives minus negatives as signed values (negatives already signed), result is NET not gross. Always emit {"answer": number}.

[experience-tool-quirks v1] experience tool usage quirks
experience `put` requires a non-empty `id` string; omitting it fails with {"error":"KeyError: 'id'"} even though the schema lists id as optional. Always pass op,id,title,content. Reusing an existing id fully replaces (bumps version). Use op:"search" (query, or empty) to list entries, op:"get" with id to read one, op:"delete" with id to remove.
