一、研究目标与判断标准

我们关心跨任务记忆对效率的影响：

- a：Agent 完成任务，产生持久化记忆。
- b：与 a 存在真正可复用的经验，记忆应当提高效率。
- c：表面与 a 相似，但关键适用条件不同；错误复用 a 的经验可能降低效率。
- 即使 Agent 在 c 中最终发现错误、恢复并答对，额外的探索、错误调用和验证成本，仍然属于有价值的负迁移证据。

最终正确性是质量约束，效率变化是主要研究对象。不能把“最终答对”当作没有负迁移，也不能把“更快地答错”算作效率提升。

目前仅初步判断这个方向“可以做”，尚未证明“值得做”。旧报告中更积极的结论，以这里的新判断为准。

重点研究两个问题：

1. Memory writer 的 scope 问题：
   Agent 从 a 中总结记忆时，是否遗漏适用条件、扩大结论范围、把局部经验写成全局规则？引导 writer 能否减少这些问题，同时保留对 b 的帮助？

2. Memory fix 问题：
   Agent 在 c 中发现记忆有误并纠正当前行动后，会不会主动修复持久化记忆？修复是否被后续任务实际读到，能否避免重复踩坑，同时保留原本对 b 有用的经验？

三、数据要求：至少 10 组有实质差异的 a/b/c

至少设计并完成 10 组，而不是 10 个任务或者同一组三次重复。可用 CL-Bench、其他公开 benchmark，或自行构建可验证任务。

任务应覆盖多种实质不同的经验及失效原因，例如：
- 数据分析中的单位、样本覆盖范围、过滤条件或关联关系；
- API 版本、参数、分页或返回语义；
- 代码仓库、构建工具、依赖或配置约定；
- 文件格式、编码、路径或表格结构；
- 项目约定、用户偏好或随时间变化的状态。

这些只是候选，不要求机械凑齐。不能主要靠更换表名、人名、数值来制造“多样性”。

每组说明：
- a 能提供什么经验；
- b 为什么可以复用；
- c 的关键边界是什么；
- Agent 能从哪些合法可见的证据发现边界；
- 如何验证完成质量和行动成本；
- 数据来源、改动和生成方法。

c 的差异必须能通过任务或环境中的证据发现，不能依赖评测者私有信息。任务应给记忆留下改善效率的空间，也避免无记忆时几乎无法完成。

真实 writer 产生的记忆是主实验对象。人工编写或故意改坏的记忆可以做诊断，但必须单独标注，不能拿来代替 writer 自然犯错的证据。

保留预先纳入的无收益、无负迁移、成功恢复和主动修复案例。若筛选了“确实写错 scope”的子集，必须同时报告总体发生率和筛选条件。

四、Agent 与 memory：尽量控制变量

以简洁、可修改的开源 Agent 为主。pi agent 是候选，已有 Hermes 是另一个候选；先核查官方源码、实际工具接口和记忆触发方式，不要根据名称假定其能力。

目标是在可行范围内覆盖：
- 至少两个开源 Agent；
- 至少两种可替换的记忆机制。

可以考虑简单文件记忆、可修改的结构化记忆、带检索的记忆系统。具体选择以源码可查、成本可控、容易记录和修改为准，不追求系统数量。

设计两个层次：
1. 同一个 Agent 更换 memory，尽量隔离记忆机制差异；
2. 同一套 memory 协议接入不同 Agent，检查现象是否依赖某个框架。

原生产品配置可作为补充，但要和统一适配器的受控实验分开报告。闭源 Agent 可以保留为参照，不作为后续修改 memory 的主要载体。

比较时固定模型、实际 reasoning 参数、工具能力、任务环境、权限、上下文和记忆预算、终止条件。先用少量代表性任务校准，不必直接跑完整笛卡尔积。

明确记录：
- 谁决定写记忆：模型、任务结束钩子、系统调度，还是用户指令？
- 谁决定读记忆：自动注入、主动搜索，还是外部检索器？
- 谁能修改/删除记忆？索引或缓存何时更新？
- 使用的是否还有独立 writer、embedding 或 reranker 模型？

如果某种机制根本不支持主动持久化修复，要标记为能力或协议限制，不能归因于模型没有修复意识。

五、关键实验分支

首先让 Agent 完成 a，核验实际落盘的记忆内容，保存快照 M_a。随后 b、c 应在独立新会话中，从相同的 M_a 副本开始，避免 b 更新记忆后污染 c。

区分以下条件，按阶段安排，不必所有组合全部铺开：

- 无持久化记忆；
- 自然生成、按实际机制读取的 M_a；
- 确保相关记忆进入上下文的诊断条件，用于区分“没读到”和“读到后误用”；
- 改进 writer 引导后产生的记忆；
- 通用提醒，例如“检查历史经验是否适用于当前任务”，作为简单强基线；
- 人工正确限定 scope 的记忆，仅作为诊断上限。

写入触发和写入内容要分开研究：原生条件未写入也是结果；统一结束时写入机会可以另设受控条件，不能冒充自然触发。

比较 writer 引导时，优先用同一份真实 a 轨迹和可见证据生成不同版本记忆，避免把 a 的探索差异混入 writer 效果。writer 不能提前看到 b/c 的答案或评测者的边界标注。

读到、搜索到、引用了记忆，都不自动等于行动依赖了记忆。结合行为轨迹和有无记忆的对照判断，证据不足时明确写“不确定”。

六、单独验证 memory fix

主实验观察自然修复，不在 c 的提示中要求“发现问题后修改记忆”。

分别检查：
1. 是否出现可观察的识错证据；
2. 是否纠正当前行动；
3. 是否提出修复记忆；
4. 是否真正更新持久化存储；
5. 后续检索是否返回更新版本；
6. 新任务是否避免同类弯路。

保存 c 前后的记忆、工具调用、条目版本和索引状态。对于没有读到问题记忆、没有发现错误的运行，单独归类；主动修复率的分母应是确实存在修复机会的运行。

在 c 之后增加独立新任务 d：
- d 是同类边界的新实例，不能只复述 c 的答案；
- 不携带 c 的对话上下文；
- 对比使用冻结的原始 M_a 和 c 后的 M_c；
- 增加明确要求修复记忆的条件，区分“不会修”和“没有主动触发”；
- 再检查原本适用于 b 的经验是否保留，避免靠删除全部记忆获得表面上的改善。

如果系统默认会检索完整历史对话，需要控制或单独分析这条信息通路，防止把历史检索的帮助误认为记忆条目被修复。

七、指标与分析

主要关注：
- 工具调用数，按工具类型区分；
- 无效、错误和重复行动数；
- 发现问题到恢复所需的额外步骤；
- 输入/输出 token、实际可核验的费用；
- 完成延迟，但考虑网络、缓存等噪声；
- 完成质量与成功率。

对每种成本 C 分别计算：
Δ_b = C(b | M_a) - C(b | 无记忆)
Δ_c = C(c | M_a) - C(c | 无记忆)

Δ_b < 0 表示正向效率迁移，Δ_c > 0 表示负向效率迁移。不要把不同成本指标随意加成一个分数。

质量可比时分析效率，同时完整报告失败和超时，不能只保留成功样本得出整体效率结论。分别报告 writer、检索、consumer、修复的成本，以及包含这些开销后的总收益。

同时记录 scope 错误类型、自然写入/读取发生率、识错率、持久化修复率、后续复发率及有效经验保留情况。

关键对照做适量重复。区分“固定同一份 M_a，重复 consumer”和“重新运行 a 产生不同记忆”两类随机性。尽量配对、平衡执行顺序，报告逐组结果和不确定性，不以少量运行宣称稳定显著。
