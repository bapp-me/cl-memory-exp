## 源码核查补充

### 记忆基线不能靠产品名称保证

LME 的 `memory_modules/codex.py` 在 759 行附近构造 `codex exec` 命令，传模型、reasoning 和额外配置；基线把轨迹以文件形式提供。没有因此确认实验打开了当前产品意义上的自动记忆，也不能假定 query 之间有连续会话。论文的“off-the-shelf”只支持具体 harness 配置下的比较。

当前公开库有 `tests/test_query_privacy.py`，检查 query metadata 不泄漏答案、题目类型等信息。本轮只审读，没有安装依赖或运行这些测试；而且接口测试不等于宿主文件系统已经隔离。源码所用宽权限调用不能原样放到含 gold 的目录运行。

V2 Online 的 `agentrunbook_online_learning.py` 会保存策略前后 hash、向 query sandbox 复制只读策略、整理后校验并处理失败。它已经是可参考的工程实现。不要把“加共享 Markdown 策略”称为新方法；也不要把策略检索收益自动归入事实记忆。

### MUSE 的公开快照不包含论文完整记忆

三个文件 `memory/procedural_memory.json`、`strategic_memory.json`、`tool_memory.json` 本轮取得的响应均为 0 字节，SHA256 为标准空文件 hash。`memory_manager.py` 的 `_load_memory` 会把空白文件解析为 `{}`；因此这不是零字节错误未被注意，而是能正常以空记忆启动的实现。

这只能说明**这个固定仓库快照里的这三个文件为空**。没有据此断言作者没有任何其他运行档案；但在未获得论文冻结快照和具体任务顺序之前，不应承诺一键复现论文最终成绩。

### TAC 的评分不是全部业务语义

抽查任务 `pm-update-plane-issue-from-gitlab-status`。题面要求检查 JanusGraph 两条 GitLab issue，再据状态更新 Plane 的状态与 sprint，直接附了两个系统 URL。

评分器前 3 个 checkpoint 看轨迹是否出现相关 URL；后两个检查第一条是否进入 Sprint 2，以及第二条是否为 completed。后两项都通过时可补满分。第一条“保持 open”未在该函数中额外检查。因此这是**一个具体的要求到评分覆盖缺口**，不是全 TAC 质量结论，也不是实际 exploit 运行。

源码：[任务](https://github.com/TheAgentCompany/TheAgentCompany/blob/98b68ef82a47690c316f42fddb05baafaab56851/workspaces/tasks/pm-update-plane-issue-from-gitlab-status/task.md)、[评分](https://github.com/TheAgentCompany/TheAgentCompany/blob/98b68ef82a47690c316f42fddb05baafaab56851/workspaces/tasks/pm-update-plane-issue-from-gitlab-status/evaluator.py)。对这种题应补充独立状态检查；修改后明确是衍生协议。

### AppWorld 的保存与隔离边界

官方指南明确每题 `/initialize` 激活不同初始状态，单 server 同时只承载一个状态；直接 API/MCP 调用完成后需 `/save` 再评分，`world.execute` 则会自动保存。终端 Agent 的可读目录不应包含完整 task specs、解答和测试。指南仍注明接入存在实验性部分，所以本轮结论是“有官方路径”，不是“已安装验证”。

许可方面，公开代码 Apache-2.0，protected 的 API 与 task 内容打包为 `.bundle`，再分发另有加密形式要求。本轮没有解包或把 protected 内容提交到本仓库。[官方说明](https://github.com/StonyBrookNLP/appworld/blob/42b5bcf3cd334fee33f0c37c02070a9f5807add5/README.md)

### 代码上下文研究的版本变化

2026-09-29 的论文 v3 将新数据集称为 CTXbench，公开仓库与 HF 路径仍为 `agentbench`。v3 描述 138 个实例，源码 README 和脚本保留 AGENTBench 命名。这里只记录版本事实，不把同名的其他 AgentBench 混入。

固定源码 `src/configs/generator_constants.py` 安装 Codex 0.55.0 和 Qwen Code 0.0.14，Claude 通过未锁定版本的安装脚本，Gemini 用 latest。论文写部分默认配置，不能据此补出所有精确 effort。复现前需补齐论文结果到实际二进制、配置和日志的对应关系。

## 原生产品基线已具备的能力

本轮重新读取的[Claude Code 官方记忆文档](https://code.claude.com/docs/en/memory)区分手写指令文件与自动积累的记忆，并说明项目范围和跨会话加载。实验必须验证原生记忆确实在对应项目路径被写入、读到，而不是因为新会话换目录而意外关闭。

[Copilot 官方 Memory 文档](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)说明仓库事实带来源引用、使用前核查当前分支、限定同仓库，未使用记录有 28 天清理机制。它目前标为 public preview。上述为官方功能说明，本轮没有实机验证；也不推断它能自动管理任意外部业务环境。

因此强比较必须保留现成能力，记录每组真实可见的信息。静态 API 文档、普通全文搜索、完整历史、原生记忆与简短手册都应在具体载体上测试；增加组件后再比一个被剥夺这些信息的基线，没有说服力。

## 其余载体为何没有优先

- **BIRD-Interact** 有层级知识库、用户模拟器、CRUD 和执行测试；这让它更贴近交互式数据工作，但很多知识已由 HKB 或模拟器提供。官方 README 说明部分 gold 和测试需邮件获取；本轮未发邮件。先确定共享数据库任务是否足够，再考虑记忆协议。[来源](https://github.com/bird-bench/BIRD-Interact)
- **Spider 2.0** 有大型 schema、文档和真实数据工作流。部分数据库需账户和云查询，官方也发布充分 metadata 的 Snow 版本。它是强文档基线的重要反例，不预设 schema 记忆仍有很大收益。[来源](https://github.com/xlang-ai/Spider2)
- **MemoryArena** 明确把一个目标拆为相互依赖的多 session 子任务。它适合检验动作与记忆协同，但不满足“仅因共用环境而相关的独立请求”这一最干净定义。[来源](https://arxiv.org/html/2602.16313v1)
- **LifelongAgentBench** 的依赖主要按 atomic skills 构造，DB、OS、KG 环境不自动意味着环境事实学习。没有核查其所有实验版本和许可，不作为即装即跑推荐。[来源](https://arxiv.org/html/2505.11942v1)
- **DeltaMem** 已明确分开 Task Tree 与 Environment Tree；ScienceWorld 实例涉及房间与物品映射，ALFWorld 更偏类别规律。适合机制研究；不能把模拟场景收益无条件外推到企业应用。本轮未确认完整发布依赖、模型预算和实验记录。[来源](https://arxiv.org/html/2606.03083v1)

## 如何复核本轮结果

在本目录用 Python 3.11+ 运行，无第三方依赖：

```powershell
python audit_public_sources.py
python audit_selected_files.py
python audit_data_records.py
```

第一步会重新解析远端 HEAD，**会生成新的来源快照**；要复核本次固定版本，应保留已提交的 `公开来源核查.json`，只执行后两步。第二步记录成功和 HTTP 错误，不接受 gated 条款；受限资源不会被当作读取成功。第三步只流式读一条上限 8 MiB 的记录，不下载全部 1.2 GB 对象。

三个输出文件分别为来源元数据、选定文件 SHA256、数据计数与限制。第三方完整源码和数据都在 `.cache/`，不提交。35 个选定文件请求中 33 个成功，2 个 APEX gated 文件返回 401；README、license 等额外来源见来源元数据文件，不重复计入这 35 个。

这些脚本不能验证模型效果、gold 语义、页面截图或 environment reset。若后续做实验，必须另存 Agent 原始轨迹、记忆快照、工具统计和完整费用，而不能拿本轮 JSON 当性能评测结果。
