# 环境知识跨任务复用的跨领域调研与选型建议

核查日期：2026-10-01。承接[上一轮总结](../2026-09-30-Training-free全景调查/调研总结与后续方向.md)，本轮不预设数据库胜出，也没有运行付费模型实验。

**后续复审已调整优先级：**用户指出我们要固定模型、改变 Agent，不能只按模型能力榜单或任务真实性选择项目。最新判断见[以 Agent 为变量的方向复审](以Agent为变量的方向复审.md)：APEX 降为后续应用验证，数据环境与 Web 企业应用保留为当前环境知识主线候选，代码方向重新保留。下文保存首轮比较材料，其中“APEX 用途首选”和预先固定 Claude Code 的方案不再作为最新立项建议。

**最贴近目标的产品是“逐渐熟悉一个项目工作区的 Agent”：通过实际任务发现文件、数据和应用之间的关系，以后处理不同请求时复用。APEX 的共享文档世界最符合这一用途；WebArena 单站是当前更适合公开验证的替代载体；AppWorld 适合验证 API 环境中的执行闭环。** 这是按用途、可取得材料和评测条件作出的选型建议，不是这三个载体已证明记忆收益的排名。

本轮最重要的新证据是 LongMemEval-V2：它确实从 WebArena 和 WorkArena 操作轨迹中提炼了环境知识问题，数据和代码可取得。但它测“查到证据后回答问题”，不是“在环境里完成一个新任务”。因此适合作为证据来源和诊断工具，不宜单独充当最终项目。

另一个重要发现是已有方法和强反证都不少：AgentRunbook 已提供文件化轨迹检索；Grounding Agent Memory 已做执行后环境核查；MUSE 已实现应用经验整理；原生 Claude Code 和 Copilot 已提供跨会话记忆。项目价值应落在特定工作方式的实际收益，不能落在“首次增加记忆、来源或验证”。

## 先明确研究的对象

|实际保留的内容|本轮分类|能否直接作为主线|
|---|---|---|
|执行中确认某份工作簿哪个 sheet 承载哪种业务口径，并保留出处|环境事实|可以，后续任务必须不同且仍依赖这个环境|
|某个部署的列表筛选语义、对象关联、工具实际返回字段|环境事实或环境行为|可以，需要在当前部署核查；不能缓存临时元素 ID|
|如何逐步创建工单、如何实现排序算法|操作 Skill|有用，但不把流程复用换名成环境事实|
|预先把全部 README、API 手册或企业文档建索引|文档 RAG|必须面对的强基线；不是从实际执行积累的记忆|
|上次订单金额、已点到哪个页面、当前任务待办|任务状态或答案缓存|通常不能作为跨独立任务知识|
|后半个任务需要前半个任务得到的结论|长任务连续性|与主线分开，不靠人为分会话制造跨任务问题|

记忆可以借用 RAG 检索，操作经验也可以保留；关键是逐条注明内容类型，分别报告它们的贡献。任务失败时观察到的界面事实可能仍正确；任务成功也不保证中间推断正确。

## 跨领域载体比较

下表中的“可复用知识”是合理的实验对象，除明确列出的公开结果外，均不代表已证明收益。环境中的任务多数由研究者设计或改编，不能称真实生产事故。

|载体|实际任务与可复用对象|知识怎样形成及监督边界|判断|
|---|---|---|---|
|**APEX 共享文档世界**|咨询、财务、法律工作；文件角色、工作簿结构、口径出处、相似文档的区别|读文件、计算、完成任务后整理；原版资料不是记忆。已有 Grounding 实验还给 curator 终局 grade|**用途首选，有访问条件**；先用咨询场景，避免一次铺满三个领域|
|**WebArena 单站**|电商后台、论坛、GitLab 等独立请求；页面能力、字段含义、对象关系|真实浏览动作及返回页面；环境重置后只保留可验证事实，不保留旧任务写入|**公开验证优先**；选一个站，按任务模板拆分|
|**WorkArena 与 WorkArena++**|ServiceNow 表单、目录、列表、工单及组合流程|同部署执行形成界面知识；组合任务本身的记忆要求可能只是同一长任务|企业用途清楚，但实例需批准；可先读 LongMemEval-V2 公开轨迹|
|**AppWorld**|通过 API 完成邮件、购物、音乐等组合操作；特定 API 语义和应用关系|API 调用、返回和错误；各题初始数据库与时间不同。函数库属于 Skill|闭环和评分较清楚；先检验是否只是重复读取现成 API 文档|
|**TheAgentCompany 与 MUSE**|GitLab、Plane、ownCloud、RocketChat 中的公司工作|操作形成平台知识和 SOP；MUSE 大量内容是程序经验，并有多轮重复练习|应用丰富但部署重；不作为最小起点|
|**代码仓库与 SWE-bench 或 CTXbench**|修复独立 issue；模块归属、构建测试约束、配置入口|亲自搜索、运行测试后形成；不同 issue 对应不同 commit，事实不能无条件跨版本迁移|原生能力与文档很强，静态上下文文件还有负面证据；暂不优先|
|**CL-Bench 数据库探索**|同库不同 SQL 问题；表列含义、关联和单位|查询观测；原协议还回传 gold，必须另做无 gold 协议|保留为低复杂度对照；上一轮的历史与文件记忆混杂限制仍成立|
|**Spider 2.0 与 BIRD-Interact**|企业数据库分析、CRUD、澄清及知识检索|schema、HKB、文档和实际查询；BIRD 用户模拟器另提供任务信息|第二数据库候选；不是现成跨任务记忆协议，账户、gold、模拟器成本需核查|
|**MemoryArena 与 LifelongAgentBench**|相互依赖的购物、搜索、旅行、推理任务，或 DB、OS、KG 技能序列|先前子任务、反馈及技能重放|概念邻近，但分别偏长任务依赖或 Skill 迁移，不作为本轮主载体|
|**ScienceWorld 等与 DeltaMem**|模拟科学环境、家务或购物；物品位置、场景规律|执行观察后分别记录 Task Tree 和 Environment Tree|可检验机制，现实用途较远；已有环境知识分离方案，不把这一设计当创新|

## 三个最值得保留的载体

### 共享文档工作区最贴近产品用途

一个工作区里，多个独立请求都要找到同一批真实材料。Agent 可以记住“证据在哪里、哪份文件适用、哪些 sheet 的含义已确认”，每次仍重新计算当前答案。这种知识比抽象解题口诀更符合本轮目标，也能支持实际办公交付。

已有直接方法依据是 [Grounding Agent Memory](https://arxiv.org/html/2609.11060v1)：GitHub Copilot SDK 驱动 CLI engine，任务结束后整理记忆，再由只读 curator 查询环境核查；主实验为 GPT-5.4、xhigh。论文将旧版 APEX 的 90 道咨询任务按六个 world 组成序列。上一轮的 96→11→6 工具调用选例仍可引用，但它混合计算流程与文件映射，不是纯环境事实消融。

**新增反证：同会话完整历史很有竞争力。** 论文 Appendix C 中，world `941eba66` 的 Full ICL 平均 reward 为 8.51，核查记忆为 8.52，工具调用分别 17.7 与 19.3；world `2a87e5cb` 则是 Full ICL 的 reward 更高。不能由此证明等效，也不能跳过 Full ICL 基线。论文的 curator 接受终局 grade，公布的前台费用排除了 distiller 与 curator，仍缺完整原生记忆设置和实现版本。

当前还必须区分**旧版 APEX、论文改编版和 APEX 1.1**。1.1 于 9 月修订，数据卡为 240 题、31 worlds，并补充用于澄清口径的工作区信息和处理多答案投机的评分。旧版 480 题和六 world 实验不能直接视为 1.1 上的结果。[修订说明](https://www.mercor.com/blog/introducing-apex-agents-1-1/)

**建议交付定位：**一个能逐渐熟悉项目材料、带证据回答并完成新请求的助手。先使用原生自动记忆加简短环境手册；只有实际观测到错误写入、遗漏有用知识或复核成本过高，才增加组件。尚无证据证明必须开发新的记忆算法。

### Web 环境有现成的环境知识证据

[LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2) 公布的题目确实包含部署专属信息。比如 `05cce9b3` 问电商后台客户页某个位置的操作按钮，`0738c1ac` 问低库存报表的列布局；`0d07143c` 问 ServiceNow 排序控件的默认字段。它们表明轨迹里存在可复用的环境信息，但记住界面细节能否减少有意义的工作仍需验证，不能把 UI trivia 的问答提升直接算作任务收益。

本轮独立统计了 451 题，其中 Web 240、enterprise 211；并读取轨迹文件第一条 `00332982`：101 个状态、100 个动作，其中 48 次切换 tab，发布标签为 failure。它是受控环境下的一条真实执行记录，但**没有记忆开关对照，行内也没有模型版本，因此不认定为记忆导致的失败，更不推算发生率**。详见[数据记录复算](数据记录复算.json)。

已有方法也很具体：AgentRunbook-C 保存原始轨迹，并用 coding agent 配合索引、脚本和操作说明查证；作者配置为 Codex 0.117.0、GPT-5.4-mini、xhigh，固定 reader 为 Qwen3.5-9B。Small 上作者报告原始 Codex 检索基线约 69.9%，AgentRunbook-C 约 74.9%，这是有力的现成基线，不是本轮复现，也不是最新原生自动记忆比较。[论文及限制](https://arxiv.org/html/2605.12493v1)

**为什么推荐先用 WebArena 单站：**站点、独立任务及自动评分都公开，不需要先获批 ServiceNow 实例。已解析的配置包含 182 道仅涉及 shopping_admin 的任务。首轮可选择这个后台的一组非重复任务，观察不同请求是否重复查找相同页面、字段或对象关系。

**不能直接沿用的部分：**LME 轨迹来自作者的具体部署，数据卡明确不把它当 live replay 数据集。我们新启动的 WebArena 不保证与它完全相同。LME 只用于理解和诊断，正式经历轨迹应在本轮固定的站点重新产生；用 DOM 节点编号或旧对象记录作永久记忆也不成立。

### AppWorld 更容易检验完整执行但概念要收紧

AppWorld 的价值在于有明确的应用 API、可重置任务和数据库状态评分，而且[官方终端 Agent 指南](https://github.com/StonyBrookNLP/appworld/blob/42b5bcf3cd334fee33f0c37c02070a9f5807add5/guides/evaluating_terminal_agents.md)已提供原生 Claude Code 等经 MCP 接入的方法。没有必要先写一个较弱的 ReAct Agent。

不过每题有自己的初始数据库和当前时间，稳定的是应用接口，不一定是业务数据。旧任务找到的某个联系人或订单不能自动跨题复用。通用分页、认证、参数类型等信息可能已在官方 API 文档中；若候选的收益只是把它再抄一遍，应定位为文档访问优化。若保留 Python helper 或步骤模板，则明确计为 Skill。

本轮核查到一个实际评测细节：通过 MCP 直接调用 API 后，需要显式保存最终数据库状态再评分；官方指南也要求把任务数据和评分资料与终端 Agent 的可读工作区隔离。否则可能出现“做完但没保存”的假失败或读取 gold 的假成功。

**建议用途：**当希望先做可运行、确定性判分的工程闭环时用它；先审查真实轨迹中是否存在超出文档直读的、具有跨任务稳定性的环境发现。如果没有，就停止把它包装成环境记忆主项目。

## 为什么暂不把代码仓库和 TAC 放第一

代码仓库用途真实，但已有 README、搜索、原生记忆和仓库索引。2026-09-29 的 [Evaluating AGENTS.md v3](https://arxiv.org/html/2602.11988v3)在 SWE-bench Lite 和 CTXbench 上发现上下文文件未带来一般性成功率改善，平均推理成本增加超过 20%。它研究的是预生成或人工上下文文件，不是从历史执行形成的记忆，因此既不能证明本方向失败，也足以反对“多放一份仓库地图就一定更好”。

本轮源码还发现其公开 harness 固定 Codex 0.55.0、Qwen Code 0.0.14，而 Claude 安装命令未固定版本。不能将这些历史实验描述为当前完整原生记忆效果。若以后选仓库，应找同一仓库多个独立 issue，隔离未来补丁与测试答案，并处理每题 base commit 不同的问题。

TAC 的优势是一个共同公司工作区。MUSE 论文有 18 题反复三轮积累、12 道困难新题的记忆对照；但它将战略、SOP、工具指导混合。全 175 题结果还包含经历任务，不能全部叫留出测试。固定公开仓库的三个记忆文件均为 0 字节，不能复原论文用的完整冻结记忆。[MUSE](https://github.com/KnowledgeXLab/MUSE/tree/63f98aaa5cd12542431308753f016ec558b392c5)

抽查 TAC 的 Plane/GitLab 状态同步任务发现，题面已经提供两个系统的直接链接，部分评分检查访问 URL，最终状态通过时还会补足分数。这不是“Agent 必须反复寻找入口”的证据；其 checkpoint 也未完整检查题面中的所有状态要求。TAC 可做后续应用扩展，但应先逐题审计评分覆盖和共享环境事实，不能用总分代替这一步。

## 先验证什么以及最小配置

建议**先做 WebArena shopping_admin 单站的知识复用可行性检查**，同时把 APEX 1.1 保留为拿到数据后更贴近产品的选择。不是先做全量 LME 问答，也不是三个平台同时安装。以下是下一轮方案，本轮没有执行。

### 零模型成本的准备关

1. 固定 WebArena commit `dce04686a56253aefba7b18a4fa0937cf1dc987b`，使用对应单站镜像，另记录镜像 digest、数据库快照和 URL 配置。确认站点能启动、能重置、评分器能读到状态。
2. 从 shopping_admin 单站题中按**不同 intent_template_id**预选约 6 道经历题、6 道留出题，包含不同业务目的。先审查题意、gold 和评分覆盖，再冻结清单，不能按某方法结果挑题。该站 26 题配置含 `fuzzy_match`，不是全部确定性评分；起步优先选结果易交叉核验的题。正式统计需要扩大规模，这只是筛查。
3. 已有具体入口：task 0 是畅销商品问题，task 11 是评论检索计数，task 41 是搜索词统计；task 0 和 task 1 共享模板 279，不能拆成“独立泛化”两侧。这些只是已读取的题目，尚未认定为有用的迁移配对。
4. 检查是否至少存在几类会被不同任务自然重复观察的稳定事实，例如已确认的报表入口、过滤语义、关联对象。只记任务答案、按钮序列或文档原句，则重新选择切片或放弃此载体。

不要复制 LME 的 gold 答案写手册。人工可以评估“这种事实可能在哪些任务有用”，但不能替 Agent 生成主实验记忆。评分器与来源审计放在 Agent 无权读取的目录或进程边界之外。

### 最小有模型实验

执行器采用**实验当日稳定版 Claude Code，加同一浏览器工具接口和可用的强 Opus 档模型，高推理配置**；精确 CLI 版本、模型 ID、推理参数和工具版本须在运行前冻结。这里不把历史 Sonnet 4.6 low 当强基线，也不承诺尚未核查账户可用性的具体模型。若该模型不支持名义上的 high，记录其真实等价配置而不是静默降级。

只需要一个本地站点、一个浏览器会话、一个完整 Agent，以及 Markdown 文件记忆。无需训练、向量库、多 Agent 或知识图谱。浏览器接口可以暴露动作、页面文本及截图，但所有组一致；评分所需的后台权限仅给评测器，不给候选特殊捷径。工具适配是研究的必要准备，不将其作为通用 Infra 项目。

|比较组|保留的能力|实际回答什么|
|---|---|---|
|原生新会话|原生自动记忆和原有文档均开启|成熟 Agent 本来能做到什么|
|原生加简短手册|以上能力，加经历任务后自动整理的冻结环境手册|简单方法是否足够|
|原生加候选记录|以上原生能力，加事实、来源、环境范围与必要复核|候选是否有额外收益；没有明确缺口时先不跑这一组|
|同会话历史|原生能力和完整可用历史，允许原生正常压缩|不切会话是否已满足实际用法|
|无跨题记忆|只关闭跨题状态，不削弱题内推理和工具|诊断复用空间，不能作为唯一被击败基线|

阶段一先比较原生、手册和同会话历史；确定有具体缺口才设计候选。每组做相同经历集，但各自真实执行和积累。经历结束冻结记忆；每道留出题从该组相同记忆起点开始，测试题新产生的信息不传给下一题。同会话组则从相同经历会话克隆或重放前缀，避免把上一道留出题的答案当额外优势；若另跑自然连续工作流，应单独报告。

首轮一个完整积累过程即可排查明显无效点，不能用于显著性结论。有正向迹象再做三轮独立积累筛查方差，最终按方差、效应大小与用途扩样。给足正常工具和推理预算，不通过强行限制探索制造缺口；所有 timeout 和失败保留在分母。

### APEX 的替代入口

若合法取得 APEX 1.1 数据，选**一个实际拥有足够不同任务的咨询 world**，先约 4 道经历、4 道留出，具体数量依据该 world 任务分布调整。使用完整原生 Agent 及相同文件工具，保留现成文档检索。先核查输入文件与 rubric 的一致性，并选择结果容易人工或程序交叉核验的任务。

不继承旧版六 world 的 ID、题数和成功标签；不自动把 task overlay 当全 world 的恒定知识。单纯扫描整个目录后生成索引的系统应列为 RAG/手册基线，只有来自实际经历的增量才叫环境记忆。

## 成功停止和成本口径

**先看是否完成任务，再看少做了多少工作。** 同时报告完整成功率、原生对而候选错的退步项、总费用、前台时长，以及探索、必要复核和正式操作的次数。页面定位次数下降但 token 或误操作增加，不算自动成功。

成本按实际账单或 provider usage 统计：

`总成本 = 经历解题 + 额外整理写入 + 后续解题读取复核 + 重试 + judge或NPC + 环境运行`

将实验评分成本与产品运行成本分别展示，但两者都进入研究预算。异步后台不是免费；缓存折扣、订阅限额和本地 GPU 时间均需记录。没有确定模型、任务分布和 trace token 数前，不给一个看似精确的美元报价。旧论文前台费用只能是历史参照。

|观测结果|项目决策|
|---|---|
|没有跨任务稳定事实，或收益完全来自旧答案与同模板复做|停止这个切片，避免把缓存答案当学习|
|普通搜索、原生记忆或一次性手册已解决需求|直接交付简单应用；不再强加记忆算法|
|只赢无记忆，输原生或完整历史|不能宣称改善主流 Agent；重新确认真实工作方式是否需要跨会话|
|正确性可接受，且计入构建维护后持续节省，能追溯到具体知识复用|进入扩大任务和第二独立环境验证|
|记忆引入新错误、维护费用抵消收益或当前强模型已低成本解决|修正有明确证据的错误，否则停止扩展|
|访问条件、环境重置或评分器无法可靠满足|更换载体；不据此否定记忆方向本身|

小样本没有观察到退步不等于证明非劣效。正式结论需预先设业务容忍界限，按独立积累轮次与任务结构处理相关性；多个工具动作、模板变体和随机种子都不是新的独立业务任务。
