# 条件性记忆复用：现有 benchmark 与下一步

日期：2026-10-01。承接用户提出的筛选标准：任务 a、b、c 表面相似，a 的某项经验适用于 b，却不适用于 c；误用时可能退步。项目仍是固定模型权重、允许改变 Agent 的 training-free 项目。

**建议：先在 CL-Bench 的数据库环境上做一套小规模衍生评测，验证正迁移与负迁移是否同时存在，再决定是否开发新机制。** 已有接近这种结构的任务和相关研究，不需要从零创造整个环境；但本轮未找到可以直接宣称“强 Agent 已验证 a→b 有益、a→c 有害”的现成环境知识三元组套件。

本轮只做公开论文、仓库和题目文件核查；没有模型调用、环境安装或数据库答案复算。题目固定版本与候选关系见 [候选记录](条件性复用候选核查.json)。以下区分结构、作者报告与待验证假设。

## 先把目标说准确

要测试的是**同一条经验在不同条件下的效用**，而不是笼统给任务贴“需要记忆”标签。

- a 中通过工具观察形成事实 m；b 可以复用 m，减少重复探索或提高正确率。
- c 与 a、b 相似，但 m 的适用条件不成立；如果把 m 泛化到 c，查询或决策可能错误。
- c 仍可能使用 a 中的其他知识。例如价格单位不能跨表搬用，但如何找 schema 的一般方法仍适用。
- a→b 与 b→a 是两个方向。知识条件相同，不保证每个方向都产生实际收益；要称“互用”，必须分别执行。
- “不适用”由环境事实确定，“有害”由同模型、同任务的配对运行确定。Agent 也可能正确忽略经验，因此不能预先保证下降。

目标应是保留 b 上的收益，并避免 c 上的损失。只测负例，会让“永久关闭记忆”成为虚假的优胜方案。

|---|---|---|

## 原题中已经有的 a、b、c 候选

本轮直接读取固定提交中的 [questions.json](https://github.com/pgasawa/continual-learning-bench/blob/5f8c50eb1e84b2eda2ef4faff757dfc812a0ea26/data/database_exploration/questions.json)。以下是题意摘要及标准 SQL 的关键条件，不是新编题目。

|角色|原题|单位相关 SQL|待检验的关系|
|---|---|---|---|
|a|Q11：电子产品中，价格不超过 40 美元且长评论符合条件时，计算一星评论占比|`items_g2.prc <= 4000`|执行中可能发现电子产品价格按美分存储|
|b|Q12：找出价格超过 50 美元、评论数及平均评分满足条件的电子产品|`items_g2.prc > 5000`|a 中确认的单位事实可继续使用；其他聚合仍需重新计算|
|c|Q2：计算价格超过 50 美元的办公用品所获评论平均评分|`items_g1.prc > 50`|不能把 g2 的单位推广到 g1；若改成 `> 5000`，价格筛选语义错误|

明确的记忆应类似“当前数据库的 `items_g2.prc` 以美分存储；依据为某次实际观察”，而不是无条件的“所有 prc 都要除以 100”。不能人为删去范围或要求 Agent 强制服从旧经验，再把失败当自然现象。

该三元组目前仅通过**源文件结构核查**。尚未证明 a 的正常执行能可靠识别单位；尚未在固定数据库中复算 gold 与错误单位 SQL 的数值差异；尚未证明正常记忆消费者会误用于 c。即使 SQL 语义不同，特定数据上的最终数值也可能碰巧相同，因此都要查。

此外，g1/g2 表名和商品类别是明显的范围线索。若普通记忆、强 Agent 或简单的表名范围过滤就能避免误用，这是一个合格的基础对照，但未必是值得复杂化的研究难题。

先使用稳定库，避免把跨范围适用性与时间迁移混在一起。单位、时间格式和布尔编码是可继续审计的条件；涉及迁移时另建切片。

## 如果自建，怎样让结果可信

优先保留现有数据库、工具接口和任务形态，只增加成对变体与评测协议。明确标为 CL-Bench-derived，不把衍生任务成绩冒充原榜单分数。

每个任务族包含经验来源 a、适用目标 b、不适用目标 c。进一步加入“描述不同但底层事实适用”的目标 d，防止最终只测文本相似度。可形成下面的对照：

|任务描述与来源经验的表面相似度|事实适用|事实不适用|
|---|---|---|
|高|应该复用的正例|容易误检索的负例|
|低|检测漏掉有用经验|普通无关记忆对照|

构造约束：

1. 差异来自可解释的环境条件，如表、租户、数据源或版本的字段语义。标明哪些差异原环境已有，哪些是受控改造。
2. 当前环境必须提供辨别条件的正常证据；不能悄悄改单位，又不给 Agent 任何可观测线索。
3. b/c 尽量只改适用条件，保留相近任务难度；原 Q11/Q12/Q2 可用于找机制，但复杂度不同，不能把跨题差异直接解释为记忆效果。
4. 每题分别比较有、无来源经验的运行，而不是直接比较 b 与 c 的得分。
5. 人工核定的正确事实可作“记忆潜在价值”诊断；最终项目必须验证 Agent 自己形成的记忆，不能只用人工精修事实。
6. 保留记忆的来源和真实范围；不恶意改写经验，不把强制服从提示当普通检索基线。
7. 用独立校验或 SQL 变异检查确认误用会改变答案。题干、gold、数据库版本和 checker 一致后才进入模型实验。
8. 开发集允许用于寻找机制；测试集按任务族、模板或环境版本留出，不能只保留某个 Agent 恰好失败的样本后声称普遍负迁移。

## 下一步执行顺序

### 第一步：做零模型调用的题目审计

从 30 道稳定原题开始，先验证上面的 Q11/Q12/Q2。检查题干与标准 SQL、数据库文件版本、单位识别依据及 checker；对错误单位 SQL 计算反事实答案。若原题不足，补少量配对变体。

产物是一张约 4–6 个任务族的候选表，每族包含 a/b/c，必要时增加 d：列明经验事实、可见证据、适用范围、错误复用方式、正确答案及变异答案。数量是试验规模建议，不是已确认存在这么多原生三元组。

不把 gold、知识依赖标签和反事实标签发给 Agent。原版任务会反馈标准答案；用于无外部监督的经验形成时应关闭这类反馈，并明确协议变化。若 Agent 只能凭典型价格猜单位而缺乏足够证据，应标注歧义或补可观察的数据来源说明，不能把猜中当知识形成。

### 第二步：先检验现象，再设计新机制

固定一个强模型及正常推理配置，使用完整 Agent、相同工具与权限。让它正常完成 a，从实际工具记录形成记忆。复制隔离环境，在新会话中独立执行 b 和 c；b 的运行不能污染 c。先冻结同一份来源记忆，隔离“怎样消费记忆”的影响；后续再比较端到端读写系统。

首轮至少比较：

- 完整 Agent，但不携带 a 的跨任务历史。单题内推理、上下文与恢复能力正常保留。
- 同一 Agent 的原生记忆；若选用框架没有原生记忆，应如实说明。
- 自动形成的简单事实手册，以及完整可用历史作为现实对照。
- 仅按相似度检索的记忆。
- 最简单的范围过滤：按表、数据源、版本检查适用性，必要时用当前工具观察复核。

暂不预设复杂新方法。若简单范围过滤已经足够，先把它做成可用 Agent 功能；不要为了研究故事故意削弱对照。

先以少量重复运行确定方向，再在冻结的留出任务族复测。任务族是相关样本单位；几个变体不能当作大量独立证据。模型比较不是首轮主变量，后续第二个模型用于检查结论是否依赖特定消费者。

### 第三步：分别报告正收益、退步和代价

|切片|要回答的问题|
|---|---|
|适用 b|记忆是否提高成功率，或在成功率相当时减少查询、时间和总费用？|
|不适用 c|加入 a 的经验后，原本答对的任务是否变错？是否出现错误单位或错误字段等可追溯行为？|
|中性与无关对照|读取或拒绝记忆是否带来无意义开销？|
|全部任务|收益是否足以覆盖经验整理、检索、适用判断、复核和恢复的成本？|

给出每题配对的“无记忆成功→有记忆失败”及反向变化，附重复运行不确定性；不把一次随机变化认定为稳定负迁移。机制诊断记录第一次关键查询的单位选择、是否复核以及是否恢复，最终仍以任务完成效果为主。

成本同时报告冷启动总成本和跨任务摊销成本；不要把记忆构建、额外裁判或后台模型调用隐藏为免费。

## 继续与停止的条件

- b 没有正确率或成本收益：这个环境未支持“值得加记忆”，先换任务或接受否定结果。
- b 有益、c 没有受害：可做一般记忆效率项目，但暂不宣称解决负迁移。
- b 有益、c 会受害，简单范围检查已解决：做简单工程方案即可，创新性另论。
- b 有益、c 会受害，强原生记忆和简单检查仍不足：才值得投入更细的检索、部分复用、当前证据复核或失效策略。

本项目的下一份实质产出应是**一套有可见环境依据、可独立判分的配对任务，以及强基线下的正负迁移记录**。先建立这个事实基础，再决定 Agent 要改哪一部分。
